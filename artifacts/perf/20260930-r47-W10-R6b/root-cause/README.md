| 候选 | 实验 | 结论 |
|---|---|---|
| settle 时长 | `--settle-s 0` vs `4`，win=30，3 轮配对 | 无效应 |

## B. 决定性杠杆：**CPU 亲和性**

| 运行方式 | cpu | tick/s | **每 tick 成本** |
|---|---|---|---|
| 不 pin（3 轮，win=15） | 0.15800 / 0.13733 / 0.16400 | 14510 / 12599 / 14880 | 10.9–11.3 µs |
| `taskset -c 0` | 0.06333 / 0.03600 / 0.03733 | 6464 / 3501 / 3414 | 9.8–10.9 µs |
| `taskset -c 6` | 0.03533 / 0.05733 / 0.06000 | 3427 / 5465 / 6058 | 9.9–10.3 µs |

⇒ **`cpu ≈ tick 率 × 每 tick 固定成本`，且每 tick 固定成本在所有情况下稳定在 ≈10–13 µs。**
钉核（降低调度机会）→ tick 率降 4× → CPU 同比例降 4×。**CPU 是 tick 率的因变量。**

## C. 机制（诚实标注置信度）

**已证实**：
- 每个 tick 的固定成本 ≈ **10–13 µs**（与项数、态、亲和性无关）；
- `state2/n=1000` 的 CPU 3.5× 极差**全部**来自 tick 率（每 tick 成本恒定）；
- tick 率与"每 tick 处理多少项"成反比：`ticks/s ≈ 100000 / (每 tick 项数)`
  （1000 项 × 100 Hz = 100 000 次心跳/s）。

**未闭环（⛔ 不声称已定位）**：为何同一二进制、同一配置下"每 tick 项数"会落到 7 或 23。
与调度机会（亲和性/抢占）相关，但**不是**被排除的 6 类参数能解释的；建议归 t32/R6 与调度器作者。
