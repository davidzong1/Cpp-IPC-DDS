# 结论（归因）：
#   · 控制面 cpu ≈ 0.019 core @1000 项 / 0.069 core @2000 项（mean_tick 10–16 us，tick 粒度为项级分组）
#   · 完整 state3 0.51–0.58 core 中，**其余 ~0.5 core 来自 RecvWorker 池**：
#     32 worker 每 100 ms 超时唤醒一次（wait_timeouts=320/10s），每次唤醒做一次
#     `collect_pending()` **O(route) 全扫** ⇒ 1000 route × 320 次/10s 是主成本。
#   · 该成本与 N_worker 几乎无关（4/8/16/32 worker 全部 ≈0.51–0.52 core）
#     ⇒ 与「每 worker 的 route 数」无关，只与「route 总数 × 唤醒次数」有关（§10.2 的口径）。
