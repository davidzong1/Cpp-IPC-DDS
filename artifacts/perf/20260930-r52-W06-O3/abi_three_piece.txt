## 3. 重编命令（与 W10 工装既有方式一致；库先重编、工装随后）
```bash
make -C build -j16                      # ① 库（RecvWorkerStats 尺寸变化的源头）
# ② 在 CMake 内的工装/测试：同一次 make 一并重编
# ③ ⛔ 不在 CMake 内的工装：逐一手工重编（命令与 W10 既有方式逐字一致）
INC="-I include -I src -I . -I 3rdparty"
LNK="-L build/lib -lipc -lpthread -lrt -Wl,-rpath,$PWD/build/lib"
for f in test/perf/w10/*.cpp; do
  b=$(basename "$f" .cpp)
  case "$b" in force_backend_unavailable) continue;; esac
  g++ -std=c++17 -O2 -DNDEBUG $INC "$f" -o "build/bin/$b" $LNK
done
g++ -std=c++17 -O2 -fPIC -shared -I include test/perf/w10/force_backend_unavailable.cpp \
    -o build/bin/libforce_backend.so     # LD_PRELOAD 注入器（不链接 ipc，不受 ABI 影响，但仍重编保持同源）
```

## 5. 陈旧工装的反证（证明本纪律不是形式）
build/bin/w10_r5_matrix.prev = 09-30 04:24 编译，而 build/lib/libipc.so.1.3.0 = 09-30 19:15 重链
运行：timeout 300 build/bin/w10_r5_matrix.prev --n 1 --domain 9900
结果：rc=134，stderr = 『*** stack smashing detected ***: terminated』（栈越界写）
⇒ 陈旧调用方按旧 sizeof(RecvWorkerStats)=176 留栈空间，新库按 216 写 ⇒ 覆写相邻栈变量。
   这正是 R0 §7 ABI 纪律与 t31-F4/t40 实测（rc=139 __libc_free）的同一根因。
