# 热闸门 1「1 MiB 档」的可复现性探针（t33）

## 为什么单做这个探针
`bash docs/hotpath_gate.sh build` 的门 1 对 1 MiB 档要求 `msg/s >= FLOOR_1M=700`
（基线 2026-09-21：1534 msg/s，下限取其一半）。我的**收口前**整闸运行该档直接
`FAILED: no message received`；而历史三个 run（W07/W08/W09）该档均 705–759 msg/s **过闸**。
⇒ 必须判定这是**回归**还是**波动**。

## 探针（每轮前按 `hotpath_gate.sh` 的 `clear_pool` 口径清理未被映射的 `CHUNK_INFO__*` 段）

| 批次 | 各轮 msg/s | 低于下限 700 的轮数 |
|---|---|---|
| 第一批（6 轮） | **1442 / 1176 / 529 / 544 / 249 / 1472** | **3/6** |
| 第二批（6 轮） | **466 / 1170 / 769 / 52 / 1428 / 1411** | **2/6** |
| 合计 12 轮 | — | **5/12** |

原始逐轮输出：`round_1..6.txt`（第二批覆盖了第一批同名文件；两批的结论同上表，均由当次 stdout 记录）。

## 结论（如实、不过度外推）
1. **不是单调回归**：同一二进制、同一命令，12 轮里 7 轮 ≥700（最高 1472），5 轮 <700（最低 52），
   另有一次整档 `no message received`。⇒ 该档在当前机器负载下**离散度极大**。
2. **与本任务改动面无关**：本任务只改 `test/perf/w10/**`（工装）＋ W10 文档＋新证据目录，
   ⛔ 未碰 `src/libipc/**` 的收/发路径（`git status` 可核）。
3. **影响**：热闸门 1 在 1 MiB 档**当前不是稳定判据**（既有波动面），
   ⇒ 我的收口结论**不以该门为准**，同时也不据此宣称「热闸通过」。
   ⛔ 建议由闸门负责方（架构负责人 / W00 射程）复核下限与采样轮次；
   本探针只提供读数，不改 `hotpath_gate.sh`（不属本任务边界）。

## 收口后重跑：过闸 ✅（但与收口前属同一波动面，⛔ 不据此宣称回归已修复）
before: 1 MiB = FAILED(no message received)；64 B = 178905 msg/s
after : 1 MiB = 1425 msg/s（≥700）；64 B = 164972 msg/s（≥80000）⇒ 过闸
12 轮 1 MiB 探针：5/12 低于下限 ⇒ **既有波动面**，与我的改动无关（我只改工装，未碰 libipc 收发路径）。
