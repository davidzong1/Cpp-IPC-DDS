# 异常轮审计（F4/R0-A1 纪律）——1/72

## 现象
| 项 | 值 |
|---|---|
| run | `A-st3-n1000-diagoff-r3`（st=3、n=1000、W=32、diag=off、round=3） |
| 时间 | 2026-09-30 04:48:23 |
| 读数 | `Δscan_rounds=0` 而 `Δscanned_routes_total=660000`、`Δwait_timeouts=19200`、`cpu=0.2916` |
| 判定 | rc=1（门禁 `有route时 Δscan_rounds>0` 未过）⇒ **未通过**（工装**没有**把它放过） |

## 为什么这不是"产品缺陷"而是**采集纪律**问题
1. **内部不自洽本身即证据**：同一个 `collect_pending()` 里 `scan_rounds.fetch_add(1)` 与
   `scanned_routes_total.fetch_add(scanned)` 是**相邻两条语句**（`recv_worker.cc:257-258`）。
   出现 `Δscanned=660000` 同时 `Δrounds=0` 在源码上**不可能**（除非 `scanned` 恒 0，
   但 660000 = 3300 轮 × 200 条 ⇒ 恰是"轮数对了、增量没被读到"的形态）。
2. **同一 sweep 期间库被并发重建**：工装编译于 04:24；`build/src/CMakeFiles/ipc.dir/dzIPC/shm_pub_sub_ipc.cc.o`
   于 **04:30:39** 被重编（随之重链库）；`recv_worker.cc.o` 于 **04:56:10** 再次重编并重链库；
   而异常轮发生在 **04:48:23**（正好落在两次重建之间）。
   ⇒ 违反 R0-A1（按值返回结构体 + 追加字段 ⇒ 所有引用方必须随库重编）。
3. **复跑不可复现**：用**重编并断言指纹**的工装，对同一配置复跑 **9 轮**：
   `rounds = 21120 / 21120 / 21092 / 21106 / 21100 / 21116 / 21106 / 21104 / 21106`，
   `scanned ≈ 659114–660000`，**9/9 全绿**且内部自洽。
   ⇒ 该现象与配置无关，与"库/工装配对"有关。

## 处置（本次已落地，作为 R0-A1 的工装侧闭环）
1. `w10_r5_matrix` 新增运行时指纹自证：
   - 开跑前从 `/proc/self/maps` 取**实际加载库**路径算 sha256，`--require-lib-sha256` 不符即 rc=1；
   - 收尾**再算一次**，若运行期间库被替换 ⇒ 直接判失败并写入门禁失败清单；
   - `manifest.json` 落盘 `lib_sha256` / `tool_sha256`。
2. 新增两条**内部自洽**门禁（把"不可能的读数"挡在门外）：
   - `Δscanned_routes_total <= Δscan_rounds × routes`；
   - `扫描量同向（rounds 与 scanned 同时为 0 或同时 >0）`。
3. 本 run 的原始证据**保留**（⛔ 不删、不覆盖），并在本条审计中标注"不作数"。

## 引用纪律（重申）
> 引用本 run 任何读数时，必须同时给出**该 run 自己 manifest.json 里的 `lib_sha256`/`tool_sha256`**；
> ⛔ 不得跨库版本引用，⛔ 不得把本异常轮计入通过率。
