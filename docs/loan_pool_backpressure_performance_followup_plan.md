依据：[原执行方案](loan_pool_backpressure_execution_plan.md)、[实施任务清单](loan_pool_backpressure_todos.md)、[性能预算及消费路径独立验收报告](../test/perf/loan_backpressure/acceptance_review/report.md)。本文记录待执行工作，以下任务尚未开始。

## 7. 扩容准入标准

所有可比配置继续使用以下预算：

| 指标 | 要求 |
| --- | --- |
| 发布及排空吞吐 | 不低于旧版的 90% |
| 发布 p99 | 不高于旧版的 120% |
| CPU/消息 | 不高于旧版的 125% |
| RSS 相对预算 | 不高于旧版的 125% + 8 MiB |
| RSS 硬上限 | 单发布者性能矩阵 512 MiB；消费矩阵 1 GiB |

进入扩容阶段前，须消除三个性能超预算项、补齐对象入口可判定对照，且完整矩阵的可靠性和内存预算继续通过。还须满足原方案的所有权与容量条件：多窗口空闲链完整，位图、outstanding 与池链一致，拒绝明确来自合法容量需求，接收持续 drain 且队列高水位受控。

满足以上条件后，再设计每话题/尺寸档容量上限、进程级及全局内存上限、独立段身份与 generation、阶梯扩容及段清理，并比较扩容开启和关闭时的完整矩阵。
