# 发布者隔离与剩余本机延迟修复执行方案

日期：2026-10-06。起点：`f0ed27f7`；既有本机生产实现：`9f536dc1`。状态：方案和诊断已交付，发布结果身份边界已修复；两个延迟候选撤回，原三项性能目标尚未达成。详细结果见 [本轮报告](shared_network_endpoint_evidence/20261006-writer-boundaries/results.md)。

## 1. 目标、范围和并行工作边界

依据 Cyclone DDS 的实体隔离思想，明确发布者身份/序号/积压/配额，减少有证据的不必要线程交接，对冷热话题和同话题多发布分别评估数据 socket/worker 与写入队列隔离。优先修复 [O24 报告](shared_network_endpoint_evidence/20261006-execution/results.md) 中剩余的三个本机延迟失败。

另一个 Agent 正在执行 [UDP 数据通道方案](topic_udp_data_channel_execution_plan.md)。本任务在独立 worktree `/tmp/dzipc-writer-boundaries`、分支 `fix/writer-boundaries-latency` 工作，不覆盖主目录尚未提交的网关、配置、benchmark.py 或证据。方案先提交，各完成节点单独提交；回主分支时仅整合本任务文件并检查冲突。团队 MCP 不可用，忽略相关工具要求。

本轮实施范围为本机发布/接收路径、必要诊断与验证；网络端点隔离继续由既有 N00～N15 方案负责。写入队列隔离先做可重复实验与语义设计，证据不支持则保留现状，不把它强行加入单发布者失败的修复。

正式矩阵要求没有其他编译或性能测试竞争。工作树隔离不等于 CPU 隔离；预先协调窗口，记录采样期间进程活动；不终止别人的任务、不修改全局电源/sysctl、不用忙轮询获得成绩。

## 2. 三项失败与证据边界

| 场景/第 1 轮 | 基线 p50/p99 µs | 原候选 p50/p99 µs | 失败与定位方向 |
|---|---|---|---|
| 1 SUB / 4KiB | 26.862 / 193.176 | 63.986 / 173.468 | p50 超限 32.124µs；发布及返回后同时增加，先测完整接收等待和交接 |
| 1 SUB / 1MiB | 108.485 / 306.545 | 120.911 / 239.776 | p50 超限 1.578µs；发布 p50 从 47.010 增至 72.503µs，验证复制及其外围开销 |

这三个 case 都只有一个发布者，且数据走本机 MPMC，不能归因于多发布写入争用或 UDP 共享。旧完整矩阵 24/27、8/9 三轮中位数和历史失败保持不变。之前 AVX2 预取/分块 memcpy 的无稳定收益结果不重复包装成新方案。

## 3. 发布者边界：保留逻辑独立性

完整消息身份沿用 `(source_gateway_epoch, publisher_id, sequence, RouteKey)`；本地纯 SHM 的通道代次、发布者注册身份单独保留，不修改现有 DZFlat/SHM 布局。RouteKey 包含完整 scope/msg_id，不能用 socket、worker 或 topic 哈希桶代替身份。

1. 每个逻辑发布者拥有序号空间、注销状态和发送配额；共享资源使用租约保活，不因一个发布者退出释放其他发布者的通道。
2. 多发布者各自串行发送与同一个发布对象被多个线程同时调用是两种测试。序号验收保留现有去重窗口，允许性与顺序契约以代码为准，不把单调分配等同提交顺序。
3. 积压至少区分 publisher、session、RouteKey、worker；同时保留进程/网关总上限。局部隔离不能将总配额乘以发布者数。
4. 可靠 request_id、pending/results、信用回收必须只有一个写 owner。取消/重复 Record/异常释放均只结算一次，不为优化直接绕过 `process_outboxes` 的账本。
5. 可靠完成仍指约定的远端 SHM 提交；不与普通 DDS write 返回混为同一指标，也不新增隐式业务重发。

状态与指标扩展遵循既有网络方案，新增诊断不要求发布者在每消息路径抢同一全局统计锁。

## 4. 减少线程交接：测量点与候选改动

真实路径分为本机直达、网络出站、远端接收三条，分别测量。当前本机关注：

```text
发布调用 → loan → 复制 → 提交/通知
                      → 等待返回 → recv → 释放接收lease → 分流入队
                      → getter出队 → 恢复后台接收 → API返回
```

诊断扩展已有内部 seam，不改公开 API。记录等待前/后、recv 前/后、入队前/后、getter 出队/返回以及 assist acquire/release；读取墙钟与线程 CPU 时间，按消息序号关联。空等/超时、混合类型消息和非调用线程接收必须有明确标记。诊断默认关闭，钩子开启时不分配、不阻塞、不逐消息写文件；原始样本批次与无诊断性能批次分开。

依证据依次评估：

- 协作等待已接管后，是否仍在每次 get 结束/开始时反复恢复后台 worker、触发无数据唤醒与重新竞争。若成立，设计有界的交接合并或只在实际需要后台进展时通知；不能让 getter 离开后消息长期无人接收。
- 同一调用线程完成 recv→入队→立即出队时，是否可以在保留校验、顺序、混合队列和配额的条件下缩短交接。不能绕过已经先入队的消息、让另一个 getter 丢数据、跳过取消检查或缩短 Sample 生命周期。
- 等待 backend 的阻塞语义、超时、通知序号和虚假唤醒是否导致额外延迟；只做事件驱动修改，禁止自旋等待数据。
- 大消息保留标准 memcpy；先核对复制次数、池分配/地址/实际容量、校验与计时外围。只在真实 SHM 对照证明有效后改变分配/复用策略，不使用调用者临时缓冲伪装成拥有生命周期的零拷贝。

所有候选必须保持消费锁、owner、取消/停止、重建 barrier 和 I5：已经取出的有效样本不因旧 generation 被丢弃。持 lease 的 seam 不允许阻塞，只有既有明确可阻塞点用于故障测试。

## 5. 冷热话题：按证据隔离 socket 和 worker

共享控制/发现继续保留。普通话题 pooled，关键话题可 dedicated socket；worker 数与 socket 数独立，独占 socket 不代表独占 CPU。完整配置、v2 目录/端点代次、FD/端口/缓冲半数预算遵循既有 UDP 执行方案，不另造不兼容实现。

固定冷热负载：热 1MiB×70Hz，冷 64B×100Hz。对照同 socket/同 worker、不同 socket/同 worker、不同 socket/不同 worker；总 W、允许 CPU、实际发送率一致。保留每轮平均值/p50/p99、队列和资源证据。若瓶颈在共享出站/控制循环，不能仅增 socket 后宣称隔离完成。

这部分由另一个任务完成，实现与本轮本机修复独立验收。本轮整合后做网络功能回归，不用网络实验替代三项本机复测。

## 6. 同话题写入队列隔离：评估设计

当前广播环共用预留/提交位置，较早预留槽位迟迟未提交会阻碍顺序消费。候选为“每 publisher 一条单写广播通道”或“少量固定分片”，保留 topic 语义，由接收者按就绪集合合并；同一 publisher 的所有调用仍经过一个提交 owner。

第一阶段仅创建独立实验工装，对照当前 MPMC，不修改生产通道格式。测试 1/2/8/32 PUB × 1/8 SUB，64B/4KiB/1MiB；控制总速率、真实重叠、热点发布者及暂停在预留之后的发布者。分别记录每 publisher 的平均/p99、每订阅者完整性与空闲 CPU。

实施前必须具备以下设计：

- 明确只保证各 publisher 的顺序还是跨 publisher 的全序；不能悄悄削弱现有可观察顺序。
- 每订阅者仍接收全部适用消息，不能把广播改成多消费者分工；动态 PUB 加入/退出通过带代次的控制目录处理。
- 新队列占用遵守全局内存/FD/等待集合预算；公平调度有包数/字节/时间上限，慢订阅者策略保持原契约。
- 样本引用计数、池复用、崩溃发布者保留槽位的回收、退役历史和取消关闭单独验证。
- 新布局显式版本隔离，可回退；同一消息禁止双路径投递。没有稳定收益不进入生产，保留当前 MPMC。

本机剩余三项没有多发布争用，评估结果不作为它们已修复的证据。

## 8. 构建、性能和证据约定

工作区使用独立 build 目录，不复用另一个 Agent 的 `build-shared-net`。基线保持原 f066a82 的库，使用同一 benchmark.cc 重编基线/候选工装；检查编译优化、实际链接库和 SHA256。诊断版本和正式版本分别记录。

本机正式矩阵保持 1/8/32 SUB × 64B/4KiB/1MiB，100Hz、预热2秒、采样30秒、3轮、baseline/shared_v1 配对次序；全部允许CPU0～31，关闭新增及已有诊断、无新增忙轮询。原阈值是候选 p50/p99 不超过基线加 `max(基线×10%,5µs)`；以原矩阵汇总脚本核对，不擅自放宽。

零损坏、零重复、零观察丢失、计划发布与实际接受/接收数一致是前提。平均值为算术平均，分位数 nearest-rank；各订阅者与合并样本分别报告。墙钟差分不跨物理主机，分位数不直接相加。正式成绩不使用跟踪/插桩窗口，短窗只筛选方向。

证据根目录：`docs/shared_network_endpoint_evidence/20261006-writer-boundaries/`。包含 `execution.md`、`diagnostics/`、`validation/`、`performance/`、`results.md`；每批 manifest 保存源码、二进制/库哈希、命令、环境允许列表、进程活动及原始CSV（可无损压缩）。结果报告应说明改动是什么、证据如何支持、剩余风险和未关闭项。

原报告不改写历史“24/27”为“27/27”；仅添加本次结果和可复核链接。只有新的完整原矩阵逐轮全部通过，才能关闭这三项。若环境不能提供独占测试窗口，继续完成设计、代码及功能验证，明确报告性能尚未验收。
