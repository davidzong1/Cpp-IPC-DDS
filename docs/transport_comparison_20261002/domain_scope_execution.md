# domain 作用域分析与执行记录

## socket 分析

当前 socket：端口为 `11451 + domain × (fnv(topic) % 10000)`（越界折回），组播只哈希 topic。domain=0 基址退化为常数，domain 相差端口窗口时可确定性同址，size_t 传入 int 丢高位；pub/sub 与 RPC 相同名字也可能共享请求端点。进程内 ChannelKey 已含 domain；仅记录 domain 并不足以隔离跨进程收发。现有 SHM 数据、控制、RPC 与本地分发已含 domain，但名字清洗会合并不同原始 topic。

## 决定

1. 共用完整作用域键：版本、通信类型、64 位 domain、UTF-8 字节长度和原始话题名。不改变用户 msg_id。
2. socket 按该键经过 avalanche 混合计算组播和五端口对齐基址（11451…32765，避开 Linux 默认临时端口），避免 domain=0 退化与偏移端口部分重叠。旧低层地址工具保留供裸 UDP 使用，高层改用明确作用域工具。
3. socket 每个数据、ACK、请求、响应、握手报文携带 32 字节固定身份头（网络序，domain 与通信类型独立字段、话题双散列）；接收端先核对身份再交给现有分片协议。有限地址空间碰撞不再直接导致串域。身份用于路由隔离，不是认证或密码学证明。
4. UDP 总载荷保持不超过 1472 字节：统一分片页改为 1440 字节，预留 32 字节身份。这样不引入额外 IP 分片。需全量重新编译消息头和通信双方；旧 wire 不兼容。scope 在建连接时计算，热路径只复制/比较固定头，无逐包身份哈希；载荷栈内封装，临时 buffer 句柄仍使用库分配器。
5. socket 验证后，将作用域键用于 SHM 固定长度名字，避免清洗冲突和长名超限；所有尺寸池继续按该通道生命周期管理。同步嗅探工具。
6. 验证同名异域、相同物理端点的身份拒绝、pub/sub 与 RPC 隔离、高位 domain、大包分片及池回收。临时构建放仓库外。
