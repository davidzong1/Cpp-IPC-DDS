固定容量实施已经完成，当前实现没有开启自适应扩容：每个话题、尺寸档和 generation 固定 `capacity=10`。带超时的有界 `loan(size, timeout)` 默认保留 1 块消费者信用（`publisher_cap=9`）；无超时 `loan(size)` 保留旧的立即借用兼容语义，允许借满 10 块但不提供等待保证。达到相应硬上限时只返回明确的 `pool_exhausted`。自动化入口 `ctest --test-dir build -R '^loan_pool_' --output-on-failure` 前序为 5/5，本轮增加复制消费、B 级直接借样及判定器回归后为 12/12，覆盖 32 发布者、8 订阅者的 raw/DZFlat 常规与 1 MiB 突发场景。UF-011 修正了旧尺寸档、段身份和偏移量具，并在 `UF011_EXPECT_LEAK_FREE=1` 下通过 40 轮无自环及最终回满检查。

压力判据始终要求每个订阅者 `received == published`，缺失、重复、损坏、乱序、非信用失败、队列驱逐均为零，池最终 `free == capacity == 10`。常规用例还要求全部尝试成功；突发用例允许有界等待后返回明确 `pool_exhausted`，并核对拒绝数与共享信用计数一致。

优化矩阵保存在 `test/perf/loan_backpressure/optimized_verified/`：raw/DZFlat、1/4/8/32 发布者、1/8 订阅者、64 B/4 KiB/11 KiB/1 MiB、0 Hz/800 Hz、每项 3 个窗口共 128/128 配置通过，所有已接受消息均可靠交付，池快照均为一致且回满。32 发布者长压力的首轮证据保存在 `stress_verified/`：11 KiB raw 和 DZFlat、1 MiB raw 均为每窗 8192/8192；1 MiB DZFlat 三个窗口分别有 7、2、6 次明确 `pool_exhausted`。随后在 `stress_rerun_verified/` 完成独立重跑：11 KiB raw、11 KiB DZFlat 和 1 MiB raw 均为 3/3 窗口 8192/8192；1 MiB DZFlat 三个窗口分别有 3、7、4 次明确 `pool_exhausted`。两轮中每个订阅者收到的数量都等于已接受数量，缺失、重复、损坏、乱序和队列驱逐均为零，池均回满。这是固定 10 块容量在合法突发下的已知边界，不应解释为数据丢失。

相关回归证据保存在 `regressions_verified/`：本地 23 个程序 145 条用例，加上无沙箱跨网络 `test_shared_net_credit` 6/6、`test_shared_net_outbox` 8/8、`test_shared_net_prebuilt` 3/3，共 26 个程序、162 条用例通过。沙箱内网络测试受网关会话限制，不能作为实现失败判据；对应无沙箱结果已单独保存。

对照证据保存在 `comparison/`。DZFlat 单发布者吞吐基本持平，32 发布者的发布尾延迟明显改善；raw 单发布者约有 18% 吞吐下降。该 raw 对照的旧基线使用的发布路径与当前显式 loan 路径并不完全相同，因此只能作为趋势参考，不能直接归因于信用等待开销。当前只满足固定容量和可靠性验收，尚未满足实施受控自适应扩容的准入条件。

原始证据保存在 `test/perf/loan_backpressure/`，包括修改前基线、128 配置矩阵、32 发布者长压力、逐 2 ms 池占用 CSV 与 JSON 索引；`git diff --check` 已通过。
