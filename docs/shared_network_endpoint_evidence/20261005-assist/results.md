## 实现与验证

shared_v1 默认启用应用线程协作接收。getter 用固定两个 futex_waitv 槽位阻塞等待 SHM 与本地通知，和后台 worker 通过消费锁串行完成 recv→入队；不新增线程，不更改队列容量或淘汰。等待持有 route lease，入睡前复核代次；取消、代次就绪、队列生产均唤醒。`DZIPC_SHARED_RECV_ASSIST=0` 或后端不支持时回退。

- 共享 CTest 36/36 与等待目标 1/1，共 37/37；公共 API 8 个、等待原语 11 个用例通过。
- ASan/UBSan（含泄漏）：共享 public_api/failure/restart/teardown 4/4 与修正后等待目标 1/1 通过。
- OFF 2/2、assist=0 回退公共 API 4/4、既定旧路径聚焦 8/8。旧 SHM 两项历史失败未关闭。
- 初次 sanitizer 发现等待测试将 `try_send` 第二个参数误当超时，实际为字节数，导致字面量越界读取；本文件全部七处已改为显式长度及超时。初次失败和最终通过日志均保存在 validation，未删除失败。
