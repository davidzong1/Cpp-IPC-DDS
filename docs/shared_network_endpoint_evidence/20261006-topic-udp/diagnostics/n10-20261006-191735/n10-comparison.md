# N10 队列拆分对比

本报告比较 N09 与 N10 的同一组诊断窗口。两批样本均为两轮、v1 pooled/v2 pooled/v2 per-topic、同进程多话题和跨进程多话题；同话题双发布者可靠场景在两批中都失败，因此不把它的超时混入延迟收益。样本来自同机隔离 IPC 命名空间和 loopback UDP，不能推导物理跨主机单向延迟。

N10 候选把 `GatewayData` 的单一事件队列拆为 FIFO 的 Result/Feedback 两队列，并在 `pop` 中最多连续取 8 个 Result 后让出一个 Feedback。记录数和字节预算、线程数、socket 数、协议和可靠事务 owner 均未改变。

## 合格样本的 API p99

下表是每个配置/布置两轮 API p99 的中位数；百分比为 `(N10-N09)/N09`。数值单位为微秒，p99 是每轮先计算再取两轮中位数。

| 配置 | 布置 | N09 p99 | N10 p99 | 差值 | 变化 |
|---|---|---:|---:|---:|---:|
| v1 pooled S4/W4 | 跨进程多话题 | 3548.05 | 3178.12 | -369.93 | -10.4% |
| v1 pooled S4/W4 | 同进程多话题 | 3638.51 | 3410.94 | -227.57 | -6.3% |
| v2 per-topic W4 | 跨进程多话题 | 3366.14 | 3097.23 | -268.91 | -8.0% |
| v2 per-topic W4 | 同进程多话题 | 3497.78 | 3080.44 | -417.34 | -11.9% |
| v2 pooled S4/W4 | 跨进程多话题 | 3217.61 | 3460.07 | +242.45 | +7.5% |
| v2 pooled S4/W4 | 同进程多话题 | 3492.93 | 3301.77 | -191.16 | -5.5% |

逐轮方向并不一致。v2 pooled 跨进程两轮分别为 +14.6% 和 +1.4%；v2 pooled 同进程两轮分别为 -17.6% 和 +7.8%。其余配置也存在一轮轻微变化或两轮幅度不同，不能把两轮中位数当作可重复收益证明。

## ACK 区间

合格样本最慢 1% API 耗时中的 `ack_receive_to_gateway_result` 占比仍在约 32.0%～42.3% 范围。两轮中位数对比为：v1 pooled 跨进程 37.9%→39.1%，同进程 37.0%→39.5%；v2 per-topic 跨进程 36.4%→38.4%，同进程 37.7%→36.9%；v2 pooled 跨进程 36.9%→37.5%，同进程 38.0%→35.2%。占比没有稳定下降，队列拆分没有消除该区间。

## 失败和正确性

- N09、N10 均为 20 个样本，均有 8 个失败样本，全部是同话题双发布者 Reliable：每个发布者发送 36 条，其中 1 条等待约 5 秒后失败。N10 没有修复该问题，也没有新增失败模式。
- N10 构建、`test_shared_net_metrics`、`test_shared_net_end_to_end` 和完整 shared_net 回归均通过；完整回归为 39/39。
- 所有 N10 原始运行、失败响应、trace 和分析 JSON 保留在本目录；N09 原始批次未覆盖。

## 决定

该候选没有形成跨配置、跨轮次可重复的净收益，按执行方案 N10 要求回退生产实现，保留设计和实验记录。后续 N11 以回退后的单一事件队列作为最终候选，重点验证完整功能、构建兼容和既有 v1 回退路径；同话题双发布者 Reliable 超时作为未解决缺陷继续保留。
