# 剩余发布与交接延迟修复

方案cb121fb，起点2a5c424（生产实现0b7d564）。历史25/27通过及两个失败保留在20261005-handoff/。

## O16 分段定位

新增默认关闭的发布测试缝，分别记录准备、loan、复制、提交前半段、实际通知和返回；新增接收恢复worker的独立计时。只在显式诊断中读取时钟，不改变数据布局。汇总器拒绝缺失/乱序/失败记录，并按同一批最慢1%调用守恒分解。

同库直接SHM入口与shared_v1入口各两场景×三轮10秒，12窗口198000次接收全部正常，开启发布/接收诊断，全部CPU、100Hz、预热2秒。这里的baseline标签仅指同库SHM控制，**不是f066a82正式基线**；不能用本批结果关闭本机验收。原始数据、命令和指纹在diagnostic-before/。

- 1MiB：shared_v1实际复制均值46.300～66.960µs，loan 0.831～2.048µs；同库SHM复制均值41.597～95.822µs，同样明显波动。证据支持先优化实际大块复制，不将全部波动解释成共享包装开销。
- 32订阅者/4KiB：shared_v1通知均值28.379～34.568µs，提交前半段0.720～1.409µs；同库SHM通知23.940～26.736µs。实际通知是提交的主要耗时，不能把整个提交归因于MPMC队列运算。
- 第一轮32订阅者恢复worker耗时p50/p99为2.228/19.415µs。源码还确认协作getter自己生产队列项时，无本地等待者也执行本地FUTEX_WAKE；worker每次wait重新分配等待数组，并在持锁状态下发交接通知。
- 诊断相关CTest5/5、Python汇总器7/7；日志在validation/。未将这些结果当作修复后的性能证据。

## O17 实施决策

1. 对共享SHM写入的大块载荷评估AVX2非临时写入，处理任意对齐、精确尾部，并在发布之前sfence；小块与不支持CPU保留memcpy。只减少写分配成本，不改复制字节数、校验或提交顺序。将单进程微基准收益作为选择依据，最终以跨进程端到端验证。
2. 本地signal和worker中断采用进程私有futex，SHM序号仍用共享futex；对应wait/wake必须一致。使用顺序一致的等待者登记与序号复查，仅在可能存在等待者时发本地通知，关闭“检查后入睡”的丢通知窗口。
3. worker等待数组改固定128槽；暂停/恢复通知移到worker表锁释放之后，保留立即恢复和force_recheck，不延迟后台drain，不把协作作用域延长到业务处理期间。
4. 覆盖非对齐/跨页复制、发布可见性、本地取消、通知早于登记、多个getter及无下一次发布的后台恢复，然后进行诊断与原完整矩阵。

此处记录实验选择，正式验收以冻结后的完整矩阵为准。

### 复制实验后的方案收敛

diagnostic-after/保留第一版非临时写入+等待修复的12窗口，copy-ab/与copy-ab-cached/分别保存同库0/1、固定CPU0/16、交换顺序的非临时和缓存AVX2复制控制（各8个6秒窗口）。非临时写入在真实SHM中退化，缓存AVX2也未稳定胜过libc；两项自定义复制及其开关均撤回，不进入最终候选。微基准轮换十个目标块的收益不能代表真实借样块复用的访问模式。

保留标准memcpy后，发布准备的修复改为：PublisherEndpoint持有绑定该publisher身份、由ClientRuntime生命周期保活的只读原子路由提示。IO线程仍在既有锁内校验并更新完整RouteState，只有已同步、版本非零且远端数量为零才置本机提示；缺失、乱序、远端加入、会话失效保持保守行为。热路径不再为每次发布争用控制IO的mutex或查找map。提示与原路由表共用8192项上限，不新增无界表；Reliable与会话健康检查保持原判据。补状态版本/远端加入/失效及生命周期测试后实施正式复测。

## O17 最终实现与行为验证

最终候选只包含原子路由提示及等待修复，标准memcpy保持原行为。worker还保存已观察的中断序号，避免控制通知恰在全扫后、wait登记前到达时丢失；无下一条数据发布仍能立即恢复后台重查。

- 共享网络CTest36/36；扩展MPMC、等待、socket和生命周期共52目标为51/52。唯一失败`test_shm_sub_dtor_gate.DtorWakeIsNotControlPlaneDriven`在保留0b7d564库上复现，属于已有旧SHM失败，不改判通过。
- ASan/UBSan（detect_leaks=1）8/8，OFF2/2，assist=0公共API回退4/4。路由提示新增用例用同控制连接的后继信用包作屏障，验证旧版本不覆盖新状态；其11个client用例在普通和sanitizer构建均通过。
- 新增检查覆盖私有signal的两种唤醒源、多个等待者、通知先于登记及登记竞争、控制通知先于wait、暂停恢复、远端加入/未同步/会话失效，以及大消息提交后立即读取完整字节。
- 旧库对照首次因备份缺少`libipc.so.6`链接而无效，日志以`invalid-soname`标识排除；补齐链接后以ldd核对真实加载旧库，再取得相同失败。最初回退过滤器只命中1项，已用正确名称补齐4项，不冒称初次4项执行。

最终短窗为2场景×baseline/shared_v1，共52800次接收，零错误/丢失/重复。1/1MiB端到端p50/p99为93.829/330.390→72.563/186.541µs；32/4KiB为61.105/206.766→45.552/219.924µs。每窗8秒、候选显式发布打点，结果仅用于确认可继续正式验收。命令、指纹和全部数据在final-short/；正式f066a82基准已用同一新版benchmark.cc重新编译。
