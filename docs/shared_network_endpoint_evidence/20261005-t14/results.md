# T14 规模、故障、公平性与性能实测

**状态：已完成本机可执行验收及覆盖审计，整体退出条件未满足。** 没有两台物理测试主机，完整阶段计时和若干矩阵仍缺项；逐轮延迟亦有退化。默认仍为 legacy，shared_v1 仅显式启用，不宣称整体低延迟优化完成。

基于 `674cbcd`。本卡补上 RouteKey 轮转发送，首发积压时以包数和最大片字节预算限制重传至本轮 50%；小于两个最大报文的预算不向上取整。旧 EAGAIN 批次也执行当前重传限额。控制发送每 peer burst 至多 16，目录待发时每九个非目录机会后预留目录机会。编码后、系统调用前复查原期限；发布者注销屏障确认前取消该发布者所有未完成网络事务，保留 ACK 数与可能投递状态。已发网络包仍不承诺撤回。

发送按话题取有限批次，并受 shard 的包、字节、时间预算约束。该实现尚未提供独立的每话题 deficit 字节权重和每话题排队分位数；不据此宣称所有拥塞负载都具备严格的字节公平性。

## 可复核结果

- 最终共享 CTest **35/35**，其中 GTest **154/154**、failure/error/disabled/skip 全为 0，其余为独立 Python 驱动。新增 4 条 GTest 覆盖重传份额、注销事务、64 位域/msg_id=0/长名及不同 K 的单次 SHM 提交。
- ASan/UBSan 专项 **8/8**（7 项 + 新重组边界专项），启用 leak 检查，无报告。
- 1/100/1000 公共话题：应用 UDP=0，网关 UDP=6。1000 话题创建约 3.87 秒，应用 FD=1007、线程=4，网关 FD=22、线程=8，SHM 实占采样约 62.7 MB。关闭后应用 FD=3、线程=3，网关 FD=18，活跃话题/句柄归零。业务 SHM FD 仍随话题增长；这不是全部 FD 恒定的设计。
- 1/8/32 本机订阅者：两套独立 IPC/mount locality 互发，全部字节一致，目标每条只 commit 一次、源注入=0，无重复回流；SIGSTOP 源网关后既有本机通信继续。
- 2/8 发布进程共享话题：退出一个后剩余发布者正常交付，目标每条只提交一次；详见 multipublisher-*.json。
- 四种故障各一次完整双向用例通过：确定性 1%/5% DATA 丢失、混合 DATA/首 ACK 丢失加重复/反序、每 256 包丢前 8 包的 burst。最终版本证据在 final-fault-*，其中 fault-PID.json 记录实际非零注入次数。只对测试子进程 LD_PRELOAD，未修改主机 tc/iptables。
- 1/2/8 目标单播：首发 DATA 包分别符合 `ceil(wire/1024)×目标数`。1 MiB 的 DATA 总发送字节分别为 1,516,704 / 2,673,472 / 10,118,464 B，包含重传 257 / 210 / 354 包。默认 2 ms 定时器在无人工故障的同机网络也有额外重传；这些单次样本不是正式吞吐或恢复 p99。
- 同/不同 shard 各 **3×30 秒**冷热窗口全部通过。热话题 1 MiB，1 秒校准后取可持续速率的 70%（约 61.6～65.8 条/秒）；冷话题 64B、100 Hz。每轮冷话题均接收 3000 条，最大到达间隔 **11.0～15.2 ms**；冷可靠完成 p99 同 shard 约 **5.75～5.81 ms**，不同 shard 约 **2.57～2.73 ms**。全部调用失败/错误/重复为零，结束后重组/目标状态归零。该吞吐校准仅为此工装单发布线程的速率，不代表物理网卡饱和吞吐。

## 纯本机性能

[完整分位数表](performance/summary.md)与原始 CSV.gz 共保存 **54 个窗口**：3 轮 × 1/8/32 订阅进程 × 64B/4KiB/1MiB 载荷 × 两模式；每轮预热 2 秒，正式采样 30 秒，100 Hz。实际 wire 比载荷多 80B。两版本同一 benchmark.cc、`-O2 -g -DNDEBUG -std=c++17`，MPMC=1、nodelet=false、接收 worker=1。基线为 f066a82 的直接 IPC_SHM MPMC；当前为 shared_v1 IPC_SOCKET 的本机短路径，不冒称旧 hybrid 的网络基准。

162,000 次发布全部接受，累计 2,214,000 次订阅交付，丢失/载荷错误/重复均为 0。九组场景的三轮分位数中位数均符合 p50/p99 初始门槛，但 **5/27 个逐轮配对不满足**。不删除不利轮次，不将三轮中位数通过解释为稳定 SLA。

54 个窗口冻结使用 **T13 `674cbcd` 二进制**；运行期间只审查/编辑 T14 网关代码，未编译或并发跑压力。二进制 SHA256 在 performance/binary_manifest.json。T14 改动不修改本机发布/订阅热路径；最终网关版本另跑上述完整功能、网络故障和冷热窗口，指纹在 final-manifest.json。未将 T13 的窗口标为 T14 全部网络代码的性能结论。

当前结果不能仅归因于某个锁或线程：基线与 shared 的唤醒方式、共享模式额外控制线程及系统调度均可能影响低频窗口。已有源码证据显示 shared 的可取消读取另有 Wake/状态锁，普通 getter 使用原队列条件变量；尚无完整阶段剖析，不能编造具体耗时归因。下一步应补阶段计时，再评估是否合并可取消队列唤醒和公共封装锁；当前不以更换整套 MPMC 为结论。
