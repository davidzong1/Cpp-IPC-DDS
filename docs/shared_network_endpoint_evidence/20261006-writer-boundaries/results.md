## 三项失败现在知道什么

|原失败|现有证据|结论|
|---|---|---|
|1 SUB/4KiB，p50|perf 两轮最慢 1% 的 waking→wakeup 均值 64.954/80.027µs，明显高于可运行后等待调度的 3.188/6.988µs|解释了本批长尾慢段，尚不能直接解释原 p50 失败；仍开放|
|1 SUB/1MiB，p50|固定核对照中 PUB 在 CPU16 的复制 CPU 均值 72.296/84.274µs，PUB 在 CPU0 的 PP 对照为 49.379/48.585µs|支持真实执行成本受发布核位置影响，仍未分离频率和缓存；保留标准 memcpy；仍开放|
|32 SUB/64B，p99|两个未观察到编译重叠的 perf 复核窗，最慢 1% 的 waking→wakeup 均值 95.049/143.774µs，可运行后等待调度为 16.405/19.039µs|尾部主要在唤醒激活区间；没有内核栈，不能指定某把锁或单纯归因于空闲态；仍开放|

三个原失败都是单发布者、纯本机 MPMC。增加 UDP socket 或为多发布者拆写入队列不能直接解释或关闭它们。

前期普通用户 perf 访问受限，见 [历史访问结果](validation/perf-access.log)；本轮已用用户授权的 sudo 完成采样，仅 perf 提权、业务降回 UID/GID 1000。逐消息调度和空闲态关联、核型对照及其局限见 [perf 结果](perf/results.md)。本轮快照确认 state2/state3 名称为 C2_ACPI/C3_ACPI，公布延迟 127/1048µs；该值不能替代实际退出耗时，也不能仅凭名称推断驱动。
