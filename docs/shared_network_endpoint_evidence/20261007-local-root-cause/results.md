## 当前能够支持的根因判断

4KiB 的应用缝显示，B 的端到端变化主要落在发布起点到 `recv_return` 之前；`recv_return→入队→出队→API` 在完整 L1 样本中只有微秒级 p99。这个结果支持“共享后端等待/唤醒或提交交接段是优先检查点”，但 A 的旧 seam 无法提供同一分段对照，且 L1 观测开销方向在 A/B、两个场景间不一致，结论只能定为定位级。

1MiB 的旧复制假设仍有合理性：大载荷需要复制，历史数据观察过复制 CPU 增加。但 D02-006 中 B 的发布 p50 只比 A 高 1.782 µs，端到端反而低 25.850 µs；这说明复制成本不是当前批次的普遍端到端主因，下一步必须在相同核型和缓冲条件下做 D07 才能判断。

32SUB 的历史 p99 假设把广播唤醒顺位和目标线程激活长尾分开是正确的分析方向；D03 只能看到应用入队到出队段，无法把其中的内核唤醒拆开。D04 由于采集权限不可用而暂停，不能用已有旧候选栈数据替代当前 A/B。
