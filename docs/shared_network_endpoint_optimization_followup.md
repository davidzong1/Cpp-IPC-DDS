# 延迟与可观测性补齐执行方案

基线：d8ead7a。沿用 shared_v1 显式启用、MPMC 本机直达、K+2 网关端点、原 deadline 与最多一次提交边界。保留 T14 全部原始结果，不能用新测量覆盖旧失败轮次。

1. 补固定容量的延迟直方图、协议/目录/配额分类计数；热路径不写文本，不按外来身份无界建表。应用与网关分别计数；每话题明细绑定已登记路由生命周期，汇总保持在控制包上限内。
2. 为共享订阅接入底层队列的可取消等待，合并重复 Wake/条件变量。仅显式共享 reader 启用，取消必须唤醒在途 getter，旧 Sample 不受影响，不丢通知。
3. 网关完全空闲时阻塞等待事件；有事务/重组/回执时仍按短定时器工作。补每 shard 字节、积压、唤醒与预算耗尽计数。
4. 从公开发布调用记录 encode/local_commit/credit_wait/outbox_wait/network_first_send/remote_commit/ack_wait/api_return。不同主机单调时钟不得相减；网关本机排队使用同 locality 时钟，跨主机只比较本地阶段和源端可靠完成时间。
5. 用协议损坏、每类配额触顶、重复片/消息、真实 ACK/丢包、迟到目录和关闭测试验证计数增量与回收。未采样/无调用的阶段必须显示 count=0，不能伪造零延迟证据。
6. 完成构建、共享/生命周期/sanitizer/旧模式测试，再冻结二进制跑正式对照。仍为三轮、每窗口至少30秒、相同编码/优化/订阅者/offered load；补CPU/上下文切换/亲和性与原始阶段记录，保存失败样本及逐轮门槛。
7. 更新缺项清单及用户说明，分实现节点提交。物理跨机主机尚未提供，该项保持“未执行”，同机隔离网络数据不能替代真实网卡证据。

成功条件：新增指标有真实非零/拒绝/回收断言；可取消等待无丢失/重复/UAF；正式性能按原门槛报告，不改门槛、不删失败。若平台调度仍导致个别轮次不满足，保留原始记录及分段证据，不宣称已全部修复。
