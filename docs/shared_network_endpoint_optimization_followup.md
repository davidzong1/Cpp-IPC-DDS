# 延迟与可观测性补齐执行方案

基线：d8ead7a。沿用 shared_v1 显式启用、MPMC 本机直达、K+2 网关端点、原 deadline 与最多一次提交边界。保留 T14 全部原始结果，不能用新测量覆盖旧失败轮次。

1. 补固定容量的延迟直方图、协议/目录/配额分类计数；热路径不写文本，不按外来身份无界建表。应用与网关分别计数；每话题明细绑定已登记路由生命周期，汇总保持在控制包上限内。
2. 为共享订阅接入底层队列的可取消等待，合并重复 Wake/条件变量。仅显式共享 reader 启用，取消必须唤醒在途 getter，旧 Sample 不受影响，不丢通知。
3. 网关完全空闲时阻塞等待事件；有事务/重组/回执时仍按短定时器工作。补每 shard 字节、积压、唤醒与预算耗尽计数。
4. 从公开发布调用记录 encode/local_commit/credit_wait/outbox_wait/network_first_send/remote_commit/ack_wait/api_return。不同主机单调时钟不得相减；网关本机排队使用同 locality 时钟，跨主机只比较本地阶段和源端可靠完成时间。
5. 用协议损坏、每类配额触顶、重复片/消息、真实 ACK/丢包、迟到目录和关闭测试验证计数增量与回收。未采样/无调用的阶段必须显示 count=0，不能伪造零延迟证据。
6. 完成构建、共享/生命周期/sanitizer/旧模式测试，再冻结二进制跑正式对照。仍为三轮、每窗口至少30秒、相同编码/优化/订阅者/offered load；补CPU/上下文切换/亲和性与原始阶段记录，保存失败样本及逐轮门槛。
7. 更新缺项清单及用户说明，分实现节点提交。物理跨机主机尚未提供，该项保持“未执行”，同机隔离网络数据不能替代真实网卡证据。

成功条件：新增指标有真实非零/拒绝/回收断言；可取消等待无丢失/重复/UAF；正式性能按原门槛报告，不改门槛、不删失败。若平台调度仍导致个别轮次不满足，保留原始记录及分段证据，不宣称已全部修复。

## O01：等待路径修复

共享订阅已合并到原队列的可取消等待；新发送就绪立即执行，空闲 shard 等待事件，待处理命令超过单轮预算时继续轮转。重组、可靠发送及回执仍保留维护定时器。reassembly/public_api/failure/restart/teardown 五组 CTest 全部通过，包含 1000 次交错发布和 8 个无限等待者取消测试。性能结论待冻结指标实现后的正式复测，不以单元测试替代。

## O02：有界指标与实际事件接线

已增加固定容量的协议、配额、复制、可靠终结和延迟直方图；网关四类 QueryState 查询与 CLI、应用 diagnostics、每话题排队及每 shard 流量/积压均接真实路径。DirectoryBudget 的每路由预留增加 `sizeof(RouteMetrics)`。所有计数为进程累计 uint64，直方图分位数明确为 log2 桶上界。没有采样的阶段保持 count=0；完整 enqueue→pull 与跨机单程等待没有测量，不以 gateway_queue_wait 冒名。

新增八条指标测试：并发桶计数、坏 magic/version/header/CRC 与来源分类、分片/消息去重区分、九种接收配额分别触顶与释放、四种发送配额精确拒绝/峰值/回收、目录费用与过期、真实 UDP ACK→可靠完成→信用回收，以及单记录信用耗尽后的实际等待采样。全量共享 CTest 36/36，ASan/UBSan（含泄漏）10/10，关闭构建选项2/2；证据在 `shared_network_endpoint_evidence/20261005-optimization/validation/`。这些测试不等于每一种控制队列拒绝分支都已独立注入，未将累计零字段当作该分支性能证据。

阶段和字节口径见使用说明。DZTX v2 保持112B，不新增逐消息前置往返，不挪用保留字段，源端与接收端单调时钟不混减。原 T13/T14 的历史结果保留；本轮最终低延迟结论以 O03 冻结二进制后的复测为准。
