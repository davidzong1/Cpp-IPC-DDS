# 本机 SHM / 跨机 UDP 混合发布订阅执行记录

## 本轮范围与约束

`IPC_SOCKET` 发布订阅改为混合传输；`IPC_SOCKET_ONLY` 保持 UDP，`IPC_SHM` 保持 SHM。RPC 不改选路协议。先实现发布者直接本机 SHM 分发与跨机 UDP；跨机统一接收转发进程作为后续工作，不在本轮加入。

1. 使用网络订阅公告与租约发现远端，不以本机注册池推断远端不存在。进程共享一个发现服务，按批发送，避免每话题发现线程。启动探测期、发现不可用时保守发送 UDP；稳态仅已知网络订阅者需要业务 UDP。未参与公告的外部监听者使用强制 UDP 接口。
2. 共享内存注册池提供本共享内存实例的随机身份；不能仅用 hostname/PID/IP 判断是否共享内存可达。共享池不可用不进入本机路径。
3. 每条普通发布先尝试本机 SHM，再按需网络发送；UDP 带来源共享内存身份、发布实例、32 位序号。本机混合订阅者在重组前拒绝已走本机 SHM 的网络副本；其他主机和 SocketOnly 接收者正常收包。发布实例重启身份更新。SHM 提交失败时本次直接返回失败，不再用 UDP 补投，防止部分投递后的重复；失败显式返回。
4. 两条接收路径通过通知合并读取，不加逐话题转发线程或轮询等待，不把 UDP 接收到的消息再次发布，避免转发环路。两腿保留各自有界队列，文档明确总队列预算。
5. reliable/blocking 发布暂保留纯 UDP 的“至少一个实际订阅者确认”契约，此次消息不走 SHM，不用 SHM 入队冒充 ACK。强制嗅探发送也只走 UDP。慢网络端不持有 SHM 块。
6. 注册池只登记一个逻辑混合端点，隐藏内部 SHM 腿；日志只在公开 API 处记一次。dzlist 显示混合传输，topic_cat、Python 观测工具按逻辑端点选择混合订阅，不能分别读两腿再拼接。
7. 校验域/消息类型隔离、同机/隔离命名空间模拟远端、混合/纯 UDP 互通、晚加入/退出、重复/乱序、池耗尽、可靠模式、重初始化及工具读取。使用私有 namespace，不修改宿主网络/共享内存配置。构建证据放仓库外，结果摘录后清理。
