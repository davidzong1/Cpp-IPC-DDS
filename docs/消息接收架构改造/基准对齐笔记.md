### 1.2 阶段 2：`RouteSession`（`include/dzIPC/shm_route_session.h`，138 行；`src/dzIPC/shm_route_session.cc`，168 行）

命名空间 `dzIPC::shm`，已跟踪。对外接口（**头文件为准**，比阶段 2 说明 §2 的代码块多一个 `release_receive()`）：

```cpp
struct ReceiveLease { std::shared_ptr<ipc::route> route; uint32_t generation{0}; };
std::optional<ReceiveLease> acquire_receive();          // stopping/rebuilding/无 route ⇒ 空
void release_receive() noexcept;                        // 每次成功 acquire 必须配对一次（含异常出口）
void begin_rebuild(uint32_t new_generation,
                   const std::function<std::shared_ptr<ipc::route>()>& create);
void stop_and_wake() noexcept;                          // 幂等，**非终态**
void wait_quiescent();                                  // 等 receive_inflight_ == 0
std::shared_ptr<ipc::route> current_route() const;
uint32_t generation() const;
```

**五条不变式（I1–I5，写死在头注释，改实现前必读）**：I1 recv 期间 lease 的 `shared_ptr` 保活；I2 只有 `inflight==0` 且已禁止新 lease 才允许 `release()`（`shared_ptr` 保证不了 `release` 与 `recv` 不并发）；I3 `stopping_/rebuilding_` 置位后 `acquire_receive` 一律空；I4 acquire/release **严格配对**（漏一次 ⇒ `wait_quiescent` 永不返回；多一次 ⇒ `size_t` 下溢同样不返回）；**I5 不丢已弹出的字节**：generation 只阻止**新的** recv 与决定何时 `release()`，**不得**因为 `lease.generation` 落后就丢掉 `recv` 已返回的 buffer。

**`begin_rebuild` 的 7 步实测顺序（`shm_route_session.cc:45-90+`）**：① 锁内 `rebuilding_=true` ② 拷出旧 route、放锁 ③ **锁外** `old->disconnect()`（叫醒卡住的 recv） ④ 锁内等 `inflight==0` ⑤ 锁内 `old->release()` + `route_.reset()` ⑥ **锁外** `create()`（可能阻塞，不得占锁） ⑦ 锁内发布新 generation、`rebuilding_=false`。`create()` 返回空或抛异常 ⇒ 保持 `route_` 空、`rebuilding_` 复位、generation 不变（可重试）。

**接口语义裁定（头文件明写）**：`stop_and_wake()` **不是终态** —— 一次**成功**的 `begin_rebuild` 会复位 `stopping_` 重新开启 lease。若不复位，"add_peer 失败 → 稍后重试"路径会让该话题**静默停摆**。

**已接入点（`src/dzIPC/shm_pub_sub_ipc.cc` 实测）**：`682` 析构 `stop_and_wake`；`713-721` `wait_quiescent` + `current_route()->release()`；`795-800` `begin_rebuild(generation, create)`；`810-816` add_peer 失败路径；`828-829` 读 `connected_id()`；`893-899` 控制面离开 Ready 路径；`955-983` 收包循环 lease + `recv(50)` + 异常配对释放。`channel_mtx_` 已整体删除（全仓仅剩注释）。

**实现语义**（`src/dzIPC/shm_pub_sub_ipc.cc:61-174`，逐条与搬移前一致）：
1. `!state || raw_data.empty()` ⇒ 返回；

### 2.2 注销第 6 步 `release_recv()` 与完整 6 步协议（契约 §4.4）

```text
remove_route(route)  —— 同步完成，返回即"worker 不会再碰这条 route"
  1. 从 worker 的 route 表摘除 + 标记 removed      // 禁止新的 recv_once
  2. wait_set.remove(token)                        // 唤醒阻塞中的 worker wait
  3. route->stop_and_wake()                        // 禁止新 lease + 唤醒 route 内部 recv
  4. 等 worker 侧 in-flight recv_once 归零           // 有界：最多一次 recv_once
  5. route->wait_quiescent()                       // 等 lease 归零
  6. route->release_recv()                         // ★ 归还收包独占（owner 回到 none）
```

**第 6 步漏掉的后果（勘误原文点名）**：`add_route` 会**永久返回 `busy`**、静默丢包。两处必须都归还：worker 路径由 `remove_route()` 内部归还；**兼容线程路径必须在兼容线程退出前显式调用 `release_recv()`**。第 4 步在 route 表锁**之外**等待（entry 由本地 `shared_ptr` 保活），因此不存在"注销等 worker、worker 等表锁"的环。

### 2.3 勘误 E1/E2/E3 的落地含义

## 5. 三条硬约束（全员执行口径）

### 5.1 文档优先 —— 但「文档」有优先级链

1. **冲突时以阶段 1-4 基准实现 + 阶段 5 契约与勘误为准**（勘误 > 契约正文）；
2. 阶段 1-4 的**说明文档**若与实现不符，**以实现为准**（B 类已逐条列出）；
3. 三份**方案文档**若与上述冲突，**以基准实现 + 契约 + 勘误为准**，并**立即回写方案文档**（t10 统一执行；t3/t4/t5 在自己合入时至少更新"与基准对齐的更新点"小节）；
4. 方案文档中"已落地/已验证"的**状态行必须据实修订**（A1/A2），不得把已被清理的成果写成现存；实测读数要标注"历史读数，来源为改造期构建产物，当前工作区不可复现"。

### 5.2 禁止跨模块耦合

- 一个模块**只改自己的文件**：`shm_ser_cli_ipc.{h,cc}` / `socket_pub_sub_ipc.{h,cc}` / `socket_ser_cli_ipc.{h,cc}`；共享层（`threepools/*`、`libipc/*`、`common/*`）由 **ipc-transport（t2）** 唯一 owner；
- 模块**只消费、不复制**共享层：不得复制 `RecvWorker`/`SocketWaitSet`，不得自行 `#ifdef` 平台分支，不得在 `socket_pub_sub` 里帮忙实现 `UDPNode` 的可等待句柄（那是 t2 的写权限）；
- 不允许"半边池、半边线程"的不可推理状态：探测结果进程内缓存、**一次失败即永久回退**，不在运行中切换后端；
- 三模块之间**不得互相 include 对方实现**；公共能力缺口走 **t2 追加接口**（如 D1 需要的 callback 处理通道、C7 需要的 `RecvWorkerPool::wakeup()`），而不是在模块里各造一份。

- `RecvRouteSource` 的 **9 个纯虚签名一字不改**；`RecvOwner`/`RecvBudget`/`RecvWorkerStats`/`RecvRegisterStatus`/`SocketWaitToken`/`SocketWaitSet`/`RecvWorker`/`RecvWorkerPool` 的既有签名与语义**不改**；冻结规则：**新增一律追加**（带默认实现/枚举尾追加）；
