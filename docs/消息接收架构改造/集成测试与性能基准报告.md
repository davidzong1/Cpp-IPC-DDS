## 3. 线程数与上下文切换 / 空闲 CPU

探针：`test/perf/out/20260927_t6_probes/t6scale.cpp`（**按当前头文件重编**，见 §10 的 ABI 陷阱说明）。
口径：创建 scale 个 socket 订阅者 + 1 发布者 → 静默窗口 2000ms，每 200ms 采样
`/proc/self/task` 线程数、`/proc/self/status` 的 voluntary/nonvoluntary_ctxt_switches、`/proc/self/stat` 的 utime+stime。

```bash
env -u DZIPC_SOCKET_COMPAT_THREAD -u DZIPC_SOCKET_RECV_WORKERS \
  .t6_probe/t6scale --scale=477 --idle-ms=2000 --sample-ms=200 --domain=122
```

### 3.1 接收线程数：不随规模线性增长

| scale | **worker（本波）** threads_max | worker threads_min | compat threads_max | **基线库** threads_max |
|---|---|---|---|---|
| 1 | **33** | 2 | 2 | 5 |
| 100 | **33** | 2 | 101 | 104 |
| 477 | **33** | 2 | 478 | 481 |
| 1000 | **33** | 2 | **abort** | （基线 1000 实测 abort：日志停在 `created 500/1000`） |

> 基线库边界说明：477（481 线程）与 511 均 rc=0 存活，scale=1000 时 abort ⇒ 与 D9 一致，触发量取决于**实际 fd 号**而非订阅个数。

* worker 路径 **threads_max 恒为 33**（= 32 个共享 worker + 主线程），scale 从 1 增到 1000 **完全不增长**
  ⇒ **不存在 per-route/per-subscription 代理线程**。
* `threads_min = 2` ⇒ 静默后共享池**整体归还**（空闲退出生效，见 §7）。
* compat 路径与基线库均为**线性**（≈1 线程/订阅者、基线 477 时 481 线程），构成对照组。
* worker 细节：`workers 32` 来自默认 `worker_count == 0 ⇒ hardware_concurrency()`（本机 32 核）。

### 3.2 上下文切换与空闲 CPU（静默 2s 窗口）

| scale | 路径 | ctx_vol | ctx_nonvol | **cpu_cores（空闲）** |
|---|---|---|---|---|
| 1 | 基线库 | 4080 | 0 | 0.025 |
| 100 | 基线库 | 7077 | 4 | 0.173 |
| 477 | 基线库 | 19325 | 201 | **1.124** |
| 1 | worker | 10 | 0 | 0.0000 |
| 100 | worker | 10 | 0 | 0.0050 |
| 477 | worker | 10 | 0 | **0.0050** |
| 1000 | worker | 10 | 0 | 0.0050 |
| 100 | compat | 10 | 0 | 0.0200 |
| 477 | compat | 10 | 0 | 0.0749 |

* worker 路径空闲 CPU 与规模**无关**（0.0050 cores），scale=477 时相对基线 **1.124 → 0.0050，改善约 225×**。
* worker 空闲上下文切换近乎为零（ctx_vol=10/2s = 5/s），基线随规模暴涨（19325/2s ≈ 9662/s）
  ⇒ 印证「空闲只阻塞在等待层，不做 50ms select 空轮询」这一改造目标。

判定：**通过**（要求 3 全部满足）。

## 4. 与 shm_pub_sub 基准的行为一致性对照

## 6. 追加B：fd ≥ FD_SETSIZE(1024) 边界量测（含基线对照）

### 6.1 探针

```bash
# 源码 test/perf/out/20260927_t6_probes/fdprobe.cpp —— 按当前头文件重编（ABI 有效，见 §10）
g++ -std=c++17 -O2 -I include -I . .t6_probe/fdprobe.cpp -L build/lib -lipc -lpthread \
    -Wl,-rpath,$PWD/build/lib -o .t6_probe/fdprobe
```

### 6.2 本波（当前库，worker 路径，**有数据流**）

```bash
env -u DZIPC_SOCKET_COMPAT_THREAD -u DZIPC_SOCKET_RECV_WORKERS \
  .t6_probe/fdprobe --scale=511 --domain=103 --idle-ms=600 --publish
```

| scale | fds_open | **max_socket_fd** | threads | 有数据流 | 判定 |
|---|---|---|---|---|---|
| 100 | 268 | 267 | 33 | 是 | ✅ 存活 |
| **477** | 1022 | **1021** | 33 | 是 | ✅ **存活**（未跨阈值） |
| **511** | 1090 | **1089** | 33 | 是 | ❌ **abort rc=134** |
| **1000** | 2068 | **2067** | 33 | 是 | ❌ **abort rc=134** |
| 511 | 1090 | 1089 | 33 | **否** | ✅ 存活（worker 的可读判据使 FD_SET 未被触达） |
| 511（compat） | 1026 | 1025 | 512 | 否 | ✅ 存活 |
| 1000（compat） | — | — | — | 否 | ❌ abort rc=134 |

**判据是 fd 号而非订阅个数**，与本报告口径一致：跨过 1024 即 abort，未跨过即存活。
独立复核结论与方案文档 C9 自述**一致**（477→1021 存活 / 511→1089 abort）。

### 6.3 基线对照（改造前基线库，ABI 匹配的 `build_baseline` 探针）

```bash
env -u DZIPC_SOCKET_COMPAT_THREAD build_baseline/bin/baseline_probe \
  --mode=socket_pub_sub --scale=1000 --send-msgs=1 --warmup=0 --idle-ms=200 \
  --domain=71 --prefix=d9base --out=/tmp/d9_base.json
```

两库行为一致，均在 ~500 订阅者处 `*** buffer overflow detected ***`（exit=134），
归一化 gdb 帧 **`FRAMES_IDENTICAL=yes`**：

```
基线库： #8 __fdelt_chk  ← #9 UDPNode::receive  ← #10 recv_chunk_common_impl ← #11 chunk_rev_topic
本波  ： #8 __fdelt_chk  ← #9 UDPNode::receive  ← #10 recv_chunk_common_impl ← #11 chunk_rev_topic
                                              ← #12 socket_sub_receive_once
                                              ← #13 SocketRecvWorker::Impl::run_budget
                                              ← #14 ...::drain_deferred ← #15 ...::loop
```

* 根因位置：`src/libipc/platform/posix/udp.h:346` 的 `FD_SET(server_fd, &read_fds)` 与 `:352` 的 `::select`
  （**行号已随 t2 改动漂移**，任务书引用的 326/332 是改动前 HEAD 行号；win 侧同构未复核）。
* 两库**都**含未定义引用 `__fdelt_chk@GLIBC_2.15` ⇒ 不是本波单独开启 `_FORTIFY_SOURCE` 的假象。

### 6.4 结论与归属

1. **既有缺陷、非本波引入**（基线库可复现同一 abort，且帧逐帧相同）。
2. 本波的效果是**把崩溃点从「每订阅者的兼容收包线程」搬进了共享 worker 线程**
   （`SocketRecvWorker::Impl::loop`），根因未变。
3. **board 的「>510 / 204 必须可测」在 socket 数据面未达成**（既有原因，非三模块移植缺陷）。
   socket_pub_sub 在**有数据流**时的可用规模上界为 maxfd ≤ 1023（本机 ≈477 订阅者）。
4. **本波不修**：修复落点为 ipc-transport（`select()`+`FD_SET` → `poll()`），不在任何任务 inScope 内。
   已登记为遗留项 **L1**，不得计为三模块移植缺陷、亦不得静默略过。

## 10. 方法与陷阱（供后续复用）

1. **`/tmp` 不跨 bash 调用持久**（本 harness 实测：写入后下一次调用即消失）⇒
   探针与证据必须落工作区内持久目录（本波用 `.t6_probe/`，镜像到 `test/perf/out/`）。
2. **预编译探针 ABI 陷阱（重要）**：`build_baseline/bin/baseline_probe_after` 是按**改造前头文件**编译的，
   而本波给 `socket_sub_ipc` 增加了数据成员（`receive_state_`/`receive_route_`/`worker_mode_`/`receive_generation_`，
   `sizeof(socket_sub_ipc)=304`）⇒ 布局不匹配，用它测当前库会得到
   `malloc.c:2617 sysmalloc Assertion` **堆损坏**，**那不是库的缺陷**。
   ⇒ 测当前库必须**按当前头文件重编探针**（本报告全部当前库读数均如此）。
   ⇒ 该二进制对**基线库**仍有效（`baseline_probe` ↔ `build_baseline/lib` 配对），故仍用于基线对照。
3. **先排除探针自身再上报**：期间两次自伤（`--k=v` 解析缺失导致误读 `worker_count=32`；
   `queue_size=8` 导致 `received=8/20` 被误读为丢包）。两次都经核对源码/参数后确认是探针问题。
4. **`env` 选项必须前置**：`env VAR=1 -u OTHER cmd` 会把 `-u` 当成命令（rc=127）。
   正确写法 `env -u OTHER VAR=1 cmd`，或先 `export`。
5. **gtest 计时会污染日志差分**：比对 worker/compat 前必须归一化掉 ` (N ms)` 与 ANSI 颜色码。
6. **`make -q` 返回 1 是正常**（`generate_ipc_messages` 自定义目标每次必跑），不代表产物陈旧。
7. **`DZIPC_SOCKET_RECV_WORKERS` 与 `DZIPC_SOCKET_COMPAT_THREAD` 都要清**，
   前者被共享层 static 缓存且**静默**改写线程数口径，风险等级与后者相同。
