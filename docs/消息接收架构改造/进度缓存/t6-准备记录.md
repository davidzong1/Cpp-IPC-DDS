### 1.5 结论与归因

1. **D9 是既有缺陷，本波未引入**（基线库与当前库 abort 帧完全一致）。
2. abort 发生在**订阅者创建期**（`InitChannel` 的收包 lambda 线程），**不是收包期**；
   `--send-msgs` 尚未开始投递就已中止。
3. 触发门槛量化：**约 500 个订阅者**即达 `fd >= FD_SETSIZE(1024)`（≈2 fd/订阅者）。
   ⇒ 「1000 订阅收包」类用例**必然 abort**，与线程池移植无关；线程数验收与收包验收**必须分开读**。
4. **行号勘误**：`FD_SET` 现位于 `src/libipc/platform/posix/udp.h:346`、`::select` 于 `:352`。
   任务书引用的 `326/332` 是 **t2 改动前**的 HEAD 行号（`git show HEAD:src/libipc/platform/posix/udp.h` 确认 326/332）。
   win 侧同构未复核。
5. **fortify 非差异来源**：基线库与当前库**都**含未定义引用 `__fdelt_chk@GLIBC_2.15`，
   ⇒ 不是当前库单独开了 `_FORTIFY_SOURCE` 造成的假象。
6. **处置**：本波**不修**（修复落点 select→poll 属 ipc-transport，不在任何任务 inScope 内）。
   t6 验收时须把 socket_pub_sub 的 scale≥1024 用例**标注为已知既有缺陷并排除**，不得计为本波失败。

## 2. 探针方案（修正版）

### 2.1 环境事实（**必须先读，否则工时浪费**）

**`/tmp` 不跨 bash 调用持久。** 实证：call N 写入 `/tmp/t6_probe.cpp`，call N+1 报
`cc1plus: fatal error: /tmp/t6_probe.cpp: 没有那个文件或目录`。
⇒ 探针源码/二进制/日志**必须**落工作区内持久目录。

**选定 `.t6_probe/`**（工作区根、隐藏目录）：
- 不违反「不往 test/ 添加文件」；
- 不与三模块 owner 的 include/src 冲突；
- 与 ipc-transport 的 `.t2_make.log` 同一做法。

### 2.2 已搭好并验证的骨架 `.t6_probe/t6_probe.cpp`

能力：
- `/proc/self/task` 线程计数（含时间序列采样，可画回落曲线）；
- `SocketRecvWorkerPool` 启停 + `stats()` 打印（`idle_exits` / `thread_restarts` / `wait_wakeups` / `wait_timeouts` / `route_count`）；
- 编译：`g++ -std=c++17 -O2 -I include ... -L build/lib -lipc -Wl,-rpath,build/lib`。

**实测（B 波形，当前库）**：

| --workers | worker_count | threads_after_start | 空闲回落 | idle_exits | restarts |
|---|---|---|---|---|---|
| 4 | 4 | 5 | 5 → 1（t=900ms 仍在，t=1200ms 已退） | 4 | 0 |
| 3 | 3 | 4 | 4 → 1（同上） | 3 | 0 |
| 0 | 32（=hardware_concurrency） | 33 | 33 → 1 | 32 | 0 |

⇒ **两个附带结论**：
- `SocketRecvWorkerPool::start(n)` 的**显式 worker_count 被正确尊重**（4→4、3→3），0 才回落 hw；
- **共享层空闲退出实测生效**：`idle_keep_alive=1000ms` 后全部 worker 退出、线程数回到 1、
  `idle_exits == worker_count`、`restarts == 0`。
  ⇒ 支持 D2 结论：`test_sercli_auto_path.cpp:337` 的 4000ms 窗口**应当能过**（实测回落耗时 ~1.0–1.2s < 4s）。
  ⛔ 不作为 t6 验收结论（模块侧 t3/t4/t5 尚未移植），仅作为共享层能力实证。

### 2.3 自伤教训（已修，记录以免复现）

骨架首版 `arg_long()` 只解析 `--key VALUE`，不支持 `--key=VALUE`；我传 `--workers=4` ⇒ 静默回落默认值 0

是**探针自身 bug**，非实现缺陷。已改为两种形式都支持。
⇒ t6 期间任何「实现疑似有 bug」的读数，**先排除探针自身**再上报。

## 3. 测量纪律（确认 + 补充第 3 条）

1. **测前必须重编**：`cd /home/zwc/cpp_ipc_dds/build && cmake -S .. -B . && make -j$(nproc)`
   —— 目前实测：`build/lib/libipc.so.1.3.0` 已于 **21:12** 被重编，
   `nm -DC` 中 `SerRequestRoute|socket_sub_receive_state|SocketReceiveWorkerPool` 计数 = **0**
   ⇒ 原「假绿符号」已消失。但 t3/t4/t5 仍将持续改码，t6 **每次**测量前仍须重编。
2. **一律** `env -u DZIPC_SOCKET_COMPAT_THREAD`；仅在需要「兼容回退路径」对照组时显式 `=1`。
3. **新增**：同时 `env -u DZIPC_SOCKET_RECV_WORKERS`。
   该变量由共享层**进程内只读一次并 static 缓存**（`socket_recv_worker.cc:80-103`），
   shell 残留会**静默改写线程数口径**（实测 start(0) ⇒ 32 = hw），使线程数读数反转且无任何报错。
4. **容量层不得混用**（实测确认两项，第三项为 captain 口径待复核）：
   - `SocketWaitSet::max_channels()`：Linux **4096**、Windows **63**（`socket_wait_set.cc:31/33`，已核）
   - worker 上限 **128**（`socket_recv_worker.cc:61`、`recv_worker.cc:64`，已核）
   - `ipc::recv_wait_set` = **127(Linux)/63(Win)**（captain 口径，未复核）
