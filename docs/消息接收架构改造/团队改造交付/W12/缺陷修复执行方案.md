## 2. 统一工作纪律

### 2.1 冻结窗口

正式复核前停止并发构建、性能采集和无关文件编辑。每次复核使用独立目录：

```text
build/<task>/<attempt>/
artifacts/perf/<run-id>/
```

不得覆盖既有 `artifacts/perf`、历史报告、历史快照或具有固定语义的目录。W05 的历史快照目录 `build/t58/w05only/` 不得再写入修复后的源码。

### 2.2 指纹与时间点

每次构建或采集都必须保存：

- 产品源码或关键文件 SHA-256；
- `libipc.so` SHA-256；
- 测试工装 SHA-256；
- 采集开始和结束时间；
- 完整命令行、环境变量和构建目录；
- 对应的 `fingerprint.txt`。

读数与库的绑定只认 run 目录的 `fingerprint.txt`。manifest 中的生成时字段只能作为历史诊断信息。

### 2.3 提交前完整性检查

提交前必须逐文件核对工作区内容与 HEAD，不能只检查 tracked/untracked 数量：

```bash
git status --short
git diff --cached --check
git diff --cached --stat
git diff --name-only HEAD
sha256sum <worktree-file>
git show HEAD:<path> | sha256sum
```

尤其检查：

```text
src/dzIPC/shm_pub_sub_ipc.cc
include/dzIPC/shm_pub_sub_ipc.h
src/dzIPC/threepools/shm_control_scheduler.cc
include/dzIPC/threepools/shm_control_scheduler.h
src/libipc/ipc.cpp
```

### 2.4 范围和写入责任

- 同一时段一个源文件只能有一个写入负责人。
- 任务的 `inScope` 必须包含所有需要新增或修改的目录，不能只列单个主文件。
- 实现者不能作为自己变更的唯一验收者。
- 复核者只读产品代码和既有证据，新增复核产物写入新的 run 目录。

## 4. 成员一：W05 socket 与数据面负责人

### 4.1 目标

关闭 `R1-W05-F1`：当 `peer_count() == 0` 但共享段仍有陈旧 `in_use` 槽位时，槽位必须被回收，且回收不能误断随后建立的活订阅者。

### 4.2 实现边界

涉及文件：

```text
include/dzIPC/threepools/shm_control_scheduler.h
src/dzIPC/threepools/shm_control_scheduler.cc
src/dzIPC/shm_pub_sub_ipc.cc
```

必须保持以下语义：

1. `on_pub_heartbeat()` 每拍无条件执行。
2. `has_peers()` 不再作为 stale 扫描的总门控。
3. 有 peer 时按 `pub_heartbeat` 每拍扫描。
4. 无 peer 时按 `peer_dead_timeout` 同量级低频兜底扫描。
5. “何时扫描”的判据只存在于 `pub_control_tick()`。
6. 进程级调度器和 `compat_control_loop()` 都只调用 `pub_control_tick()`。
7. 不向 `PubControlState` 增加数据成员，不改变其 ABI 布局。
8. 每个驱动方独立持有自己的 `PubTickState`。

### 4.3 执行步骤

1. 机械检查发布侧入口：

   ```bash
   rg -n "has_peers|on_pub_stale_scan|pub_control_tick" \
     include/dzIPC src/dzIPC
   ```

   确认只有两个驱动调用点，实际判据只有 `pub_control_tick()`。

2. 检查节拍状态转移：

   ```text
   首次 tick                  -> 只设置 next_stale_due
   有 peer                    -> 每拍扫描
   无 peer且未到期             -> 不扫描
   无 peer且到期               -> 扫描并重新安排 next_stale_due
   ```

3. 构建并运行默认臂和 L1 回退臂：

   ```bash
   build/bin/test_w05_stale_slot_gate
   build/bin/test_w05_stale_slot_gate_arm
   DZIPC_SHM_CONTROL_SCHEDULER=1 build/bin/test_w05_stale_slot_gate
   ```

   每个臂至少运行 3 次，要求 stale 槽位回收、新订阅者不被误断、400 条消息全部收到。

4. 建立反向验证变体：

   - 删除 `pub_control_tick()` 的无 peer 兜底分支；
   - 只删除默认调度器调用；
   - 只删除 L1 回退线程调用。

   预期结果：删除公共兜底逻辑时两臂同时失败；只删除一个驱动调用时对应臂失败、另一臂通过。

5. 检查 ABI：

   - 对比修复前后 `sizeof(PubControlState)`；
   - 使用 `nm -DC` 比较导出符号名集合；
   - 确认 `pub_control_tick()` 未成为导出符号。

### 4.4 交付物

- 产品代码变更；
- 双臂 3 次重复日志；
- 反向消融矩阵；
- ABI 对照结果；
- 新 run 的 `fingerprint.txt`；
- 变更文件、命令和限制说明。

## 7. 成员四：共享层负责人，W09 修复保护

### 7.1 目标

保护 `src/libipc/ipc.cpp` 中 `reclaim_orphan_segment()` 的并发修复，防止同一 chunk 被两个 route 同时持有。

### 7.2 必须保持的顺序

在 `handles_` 的 `lock_` 临界区内完成：

1. 获取 `handles_[prefix]`；
2. 判断首次 attach；
3. 建立 handle；
4. 判断池是否 pristine；
5. 获取 `orphan_snap`。

释放 `handles_` 锁后执行锁外 `/proc` 探活；随后在 `info->lock_` 下比较快照，只有完全一致时才 `reset_free_chain()`。

不得把快照移出 `handles_` 临界区，不得删除 `memcmp` 复核，不得把 `/proc` 扫描放进自旋锁，也不得改变 `published()` 保护语义、段名或容量布局。

### 7.3 执行步骤

1. 机械检查：

   ```bash
   rg -n "orphan_candidate|orphan_snap|reclaim_orphan_segment" \
     src/libipc/ipc.cpp
   ```

2. 确认锁序始终为：

   ```text
   handles_.lock_ -> info->lock_
   ```

3. 使用同一测试二进制准备五个库：

   ```text
   BASELINE
   ABLATE：删除 reclaim 调用
   V2NEG：快照移到 handles_ 锁外
   FIXNEG：保留 reclaim 但破坏正确临界区
   FIX：当前修复
   ```

4. 使用专属前缀、8 个话题并发首借，至少 1200 轮。不得使用空前缀，也不得每轮清段导致被测路径不执行。

5. 预期：`FIX` 为 `bad_rounds=0`，`V2NEG` 和 `FIXNEG` 必须出现 `bad_rounds>0`；`BASELINE` 和 `ABLATE` 用于区分缺陷是否由 reclaim 引入。
