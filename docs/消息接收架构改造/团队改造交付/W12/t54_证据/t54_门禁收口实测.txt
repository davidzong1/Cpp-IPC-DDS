## 6 门禁纪律补充（t54 回执后，架构负责人追加；含一处**对口头转述的更正**）

### 6.1 判据量 vs 观测量（已写入 W00 A8 段，append-only）
- **判据量**（决定退出码）：**计数错误**（>0 ⇒ exit 1）—— 唯一可据以判「通过/不通过」的量。
- **观测量**（不判定、不计失败、**随时点变动**）：`unverifiable` / `已漂移` / `一致` / `大偏移不可判定`。
- **引用格式**：要么省略，要么写「`unverifiable = <N>`（**<run 时刻> 读数**，非判据）」。⛔ 不得写成固定常量、⛔ 不得用其增减宣称门禁变好/变坏。

### 6.2 可逆注入实测（我方 + 文档负责人各做一次，结论一致）
| 注入行数 | unverifiable | 计数错误 | exit |
|---|---|---|---|
| 0 | 232 | 0 | **0** |
| 1 | 233 | 0 | **0** |
| 2 | 234 | 0 | **0** |
| 3 | 236→（我方）／文档负责人 +2 档 | 0 | **0** |

⇒ **线性 +N**：新增 N 行无锚点符号引用使**观测量正好 +N**，而**判据量与退出码恒不变**。

### 6.3 ⭐ 一条**自查并修正**的自指污染（我方）
我写「随时点变动」纪律时把演示文字写成了**可匹配形式**（`basename:NNN` 的真实数字写法），于是**门禁把自己的纪律文本当成真实引用** ⇒ `unverifiable 232 → 233`。
- 可逆编辑实测：改写成非匹配占位（`basename:NNN`）⇒ **回到 232** ✅
- ⇒ 纪律：**门禁文档讨论行号口径时，示例必须写成不可匹配形式**，否则「记录测量的文字」会改动「被记录的量」。

### 6.4 ⛔ 对一条**口头转述的更正**：「换扫描根会改变计数」**不成立**
文档负责人提出「副本作 `--scan` 根 ⇒ 基线 233 而非 232」。我按**同一次命令调用内、两树 `diff -r` 逐字节相同（各 235 文件）**重做对照：
```
--scan docs            ⇒ unverifiable=232  计数错误=0
--scan /tmp/rootprobe  ⇒ unverifiable=232  计数错误=0   ← 完全相同
```
⇒ **扫描根不是变量**。先前观察到的差异实为**时点/内容差异**（其第一版副本含当时尚未修正的行）或**副本被环境清空**所致。
⚠️ **连带发现的环境事实（做反控必须知道）**：本机 `/tmp` **跨 bash 调用不保留** ⇒ 反控样本**必须在同一次调用内创建并消费**，否则会得到 `unverifiable=0` 这类「看似门禁失效」的**假读数**（实测遇到）。这与「不加锚定声明 ⇒ 反控假通过」是**同族陷阱**：**假读数既可能来自"没判"，也可能来自"没读到文件"**。
