## 4. 我在本轮发现的**方法论坑**（一并报告，避免下游重踩）

1. **整文件的 `return` 多重集不能当作某个补丁的判据**：`src/dzIPC/shm_pub_sub_ipc.cc` 被 W05/D-22/W08 三个
   改动先后触及，按**文件**比对会看到 **71 个新增 return**（绝大多数与本补丁无关），从而误判「有行为变更」。
   正确做法 = 按**补丁**的 `+`/`−` 行做多重集（我据此得 `so==sn` ⇒ 无行为变更）。
2. **静态 grep 会漏掉「数值来源」这类问题**：§0/§1.2 的数值不含 `r05`/`r10` 字样，grep 旧 run_id 只能抓到
   banner 与 §7/§10，抓不到 §0/§1.2。⇒ 对「已声明失效」的证据，判据必须是**数值溯源**（逐格比对+反查），
   不是字符串搜索。
3. **`poll` 的 `timeout` 是 `int` 毫秒，`select` 的 `timeval` 能装更大值**：迁移时若不处理
   （W07 处理了：`INT_MAX` 截断 + 保留 `remaining_ms` 外层循环），会在超大 `tm` 下**缩短总等待**。
   我确认现状实现**未引入**该缺陷。
