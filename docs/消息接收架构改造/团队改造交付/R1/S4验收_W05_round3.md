## 1. N1（high）：F1 的实体修复只覆盖一条驱动路径；L1 回退仍带正确性回归

### 1.1 事实：门控在**驱动方**，而修复只改了其中一个驱动方

修法是把调度器 `dispatch()` 里 `if (has_peers) {…}` 改成「真 ⇒ 每拍扫；假 ⇒ 低频兜底扫」
（`src/dzIPC/threepools/shm_control_scheduler.cc:368-380`，已落地 ✅）。

但 W05 的**回退路径**不使用调度器 —— 它用**每条话题自己的**兼容驱动线程，
而那个循环里**自己又写了一遍同一道门控**：

```cpp
// src/dzIPC/shm_pub_sub_ipc.cc:930-943  compat_control_loop()（⛔ t77 未改）
while (running.load(std::memory_order_acquire))
{
    if (pub_control_state_ != nullptr)
    {
        pub_control_state_->on_pub_heartbeat(dzIPC::shm_control::ControlClock::now());
        if (pub_control_state_->has_peers())                    // ← 同一道门控，原样保留
        {
            pub_control_state_->on_pub_stale_scan(dzIPC::shm_control::ControlClock::now(),
                                                  kControlTiming.peer_dead_timeout);
        }
    }
    std::this_thread::sleep_for(kControlTiming.pub_heartbeat);
}
```

全仓 `on_pub_stale_scan` 的调用点只有三处：调度器两处（修复后）+ **兼容循环一处（未修）**。
