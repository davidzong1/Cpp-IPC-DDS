### 2.2 v2 的两个前提：**前提① 不成立**（high）

交付 §2.1 的论证原文：

> ① **本进程此刻尚未持有本档任何 chunk**。取"首次 attach"这一刻即天然满足：
>   要持有本段的 chunk，必须先映射本段；而本函数只在 `handles_[prefix]` 由"无效"变为"有效"的那一次被调用
>   ⇒ 此前本进程不可能从本段借出过任何东西，也不可能持有接收侧的 `buff_t`。

**代码事实**（`src/libipc/ipc.cpp:536-563`）：

```cpp
{
    std::lock_guard<std::mutex> guard{lock_};        // ← handles_ 的锁
    h = &(handles_[pref]);
    newly_attached = !h->valid();
    if (!make_handle(*h, shm_name, chunk_size)) return nullptr;
}                                                     // ← ★ 此处**释放** lock_
auto *info = static_cast<chunk_info_t *>(h->get());
if (newly_attached)
{
    (void)reclaim_orphan_segment(info, pref, chunk_size, "attach");   // ← ★ 锁外调用
}
return info;
```

而 `reclaim_orphan_segment()` 内部（`:453-488`）**先取一次池锁做素净判定、再取一次做快照、再取一次做复核**，
三次都在**不同的临界区**，且中间夹着毫秒级的 `/proc` 扫描。

⇒ **存在这个窗口**：
1. 线程 A 走完 `make_handle`，把 `handles_[pref]` 置为 **valid**，**释放 `lock_`**；
2. **线程 B**（同进程、**同一 prefix** —— 由 §1.3，**同一档池**的不同话题就是这种情况）此时调 `get_info()`：
   `h->valid()` 已为真 ⇒ `newly_attached == false` ⇒ **B 直接拿 `info` 并 `acquire()` 借出 id#0**；
3. 线程 A 进入 `reclaim_orphan_segment()`：素净判定读到 **非素净**（`cursor_ != 0`，因为 B 已借出）⇒ **不是**素净初始态；
4. A 取快照（此时 `cursor_ == 1`）、锁外扫 `/proc`、**重锁复核 —— 快照与当前一致**（B 在这段窗口内没有再动池）⇒ **复核通过**；
5. A 执行 `reset_free_chain()` ⇒ `cursor_ = 0`、整表重init ⇒ **B 已持有的 id#0 被重新置为"空闲"** ⇒
   后续任何借出都会**再次发出 id#0** ⇒ **同一块 chunk 被两块借样同时持有**。

⚠️ **这不是"v2 写错了"，而是 v2 的**前提①**写错了**：前提①要求"本进程此刻尚未持有"，但代码只用
"`handles_[pref]` 由无效变有效"近似它 —— 这个近似**只在单线程下等价**。`reclaim_orphan_segment`
自身在注释里也承认前提①，却没有**任何机制**去检查它（既没有"本进程在飞的借样数"，也没有 owner 表）。
