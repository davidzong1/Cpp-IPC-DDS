## 1. 冲突面

| 侧 | 位置 | 写什么 |

| W08（已入库，D-3 有界例外） | `src/dzIPC/common/nodelet_config.cc:72/76/80`（`NoteDzFlatPathDelivered`） | `tlv_messages` / `dzflat_a_messages` / `dzflat_b_messages` 各 +1；并累加 `*_wire_bytes` |

## 2. 实测（`artifacts/perf/20260928-r19-W02`，dzIPC 三档 15×3 = 45 case）

- 恒等式 `family − (pub_dzflat + pub_fallback) == sent_ok`（family = tlv+a+b）**严格成立 27/45**，其余偏差 **−2~−3**（末几条钩子计数落在 harness 读取窗口之外，方向单一）。
- **45/45 的 `family > sent_ok`**（即发生双记）。
- 例：`r2_tlv_full_blocking_64B_1000Hz`：`sent_ok=1000`、`tlv_messages=3212`；
  `r32_dzflat-b_full_blocking_64B_1000Hz`：`sent_ok=1000`、`dzflat_b_messages=3199`。
- cyclonedds 两档 15×2 = 30 case **不受影响**（`family=0`，dzIPC 计数器在该路径不被写）。
- 逐 case 明细见证据文件。

## 3. 影响面（⛔ 不外推）

- **不受影响**：`sent_ok` / `recv_measure` / `send_failed` / 延迟分位（均 harness 自算，不读注册表）。
- **受影响**：直接读 `counters.json` 的 `*_messages` 会得到约 **2×** 条数。
  由于 W03 `path_evidence.h` 把 `counters` 当作"该路径独立计数"来判 `confirmed`，
  该 2× 会进入 `path_evidence.json` 的样本数解读（当前 `confirmed=[tlv, dzflat-a, dzflat-b]`）；
  W11 若引用同一 counters 也会被带偏。
- **W08 自身不受影响**：`test_w08_dzflat_ab` 的路径断言用**差值**（before → +1）且在同一进程内只由钩子写；
  r11..r16 的 `counters_publisher.json` 来自 W08 自己的 writer 进程，无 W02 行内 inc。
