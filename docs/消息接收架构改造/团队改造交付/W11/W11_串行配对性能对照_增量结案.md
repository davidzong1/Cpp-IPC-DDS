## 1. 串行配对实验的组织（独占窗口）

### 1.1 独占窗口与串行纪律

- **单进程串行**：全批 63 个 run **顺序执行**，任一时刻只有**一个**被测进程（⛔ 无并发基准、⛔ 无"最优轮挑选"）。
- **逐 run 记录机器负载**（`runs.tsv` 第 12 列，前 3 个 loadavg 值）：全批落在 **1.2–3.2**，
  无"高负载轮"被静默混入（对照 §5 的 r31/r32 反例）。
- **逐 run 独立进程 + 逐 run 唯一 domain**：池的 worker 数由**首个 `start()` 调用方**一次性决定
  ⇒ 同进程跑多档会**串档**；domain 逐 run 唯一以防 SHM 段残留互见（沿用 t38 的做法）。

## 2. 实验组 A：控制面 CPU（与扫描成本**分列**）

### 2.1 归一化形态（W00 §11.3 R-3）

```
cpu ≈ k_态 × 注册项数 × tick_率
其中 k = 每注册项每 tick 成本

每 tick 成本(µs/tick)  = cpu_cores ÷ tick_rate × 1e6
每注册项(ns/项·tick)   = cpu_cores ÷ (注册项数 × tick_rate) × 1e9
⇒ 两者相差因子 (1000 ÷ 注册项数) —— ⛔ 恒不相等，不得互换
```

> ⛔ **不得使用 t45 原表的 `45.2`**：那一列的实测值是**每 tick 成本（µs/tick）**，不是每注册项

### 3.3 ⛔ 扫描成本**不是** CPU 达标/不达标的唯一归因

- 同窗口（`state3/n=1000/W=32`，diag=on）**控制面 cpu 中位 = 0.244 core**
  （5 轮 = 0.25627/0.24418/0.24891/0.17772/0.22693，其中第 4 轮即 §7 的失败 run，剔除后中位 0.2489）；
  扫描成本折算 **49.7 ns/条目 × 31.25 条目/轮 × 21150 轮 = 0.0328 s 墙钟/60 s ≈ 0.000547 core（单线程口径）**。
- ⇒ **控制面 / 扫描 ≈ 446×**（本批实测：`0.244 core ÷ 0.000547 core`；剔除失败轮为 455×）；
  t32 用原生计数归一到「项访问/s」得 **3112×** ——
  两数量级一致，都指向 **真因是 `ShmControlScheduler`**，不是接收池扫描。
  ⛔ **不得**把扫描当作 CPU 不达标的唯一归因。

3. **完整读取（②）三档同形**：TLV / A / B 在三个尺寸档上分别为

   （与 t47 的 B)⑥ 更正一致：可分性**只在发布侧**）。

**⛔ B 相对 A 的收益（禁止倍数表述）**：

- **唯一稳定的一格**：`img880k`（0.88 MB）permsg 档，e2e **B − A ≈ −29.5 µs（−7.6%）**，
  且 A 的 6 轮 e2e 极差仅 **1.03×**（386.5–398.3 µs）⇒ 该差值**可引用**。
- **小尺寸档不可引用**：A permsg 的 transport 亦呈**双峰**（6 轮 `[3.30, 5.76, 5.64, 3.36, 5.66, 5.65]` µs）
  ⇒ 66k/262k 上"B − A"被 A 的模式差异放大到 −36% / −46%，**属采样不稳，⛔ 不作结论**。
  （同一现象也在 B 上出现，见上方细化表 ⇒ 两档的模式切换是**同源**的采样现象。）
- 统一表述：**「B 只等于省掉一次 0.88 MB 拷贝」+ e2e B vs A ≈ −7%**（本批 −7.6%，与 W08 的 −6.9% 同量级）。

  —— 它只反映"发布路径少了一次 0.88 MB 拷贝"，而端到端只体现 ≈ −7%。
  ⛔ 全文**不出现「提升 N 倍」式结论**（本包已逐句检查）。
