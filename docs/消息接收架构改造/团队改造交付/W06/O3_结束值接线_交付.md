## 1. 接线点与落点（逐条）

### 1.1 接线前 / 接线后

| | 接线前（t44 接口已落、无人调用） | 接线后（本包） |
|---|---|---|
| `grep -rn "finish(" src/` | **0** | `recv_worker.cc:308` |
| `scan_ready_routes_total`（diag=on） | **0**（恒） | 非 0（四档 508…1186） |
| `deferred_depth_after_{last,max,total}` | **0**（恒） | 非 0（last 1–4、total 1016–2372） |
| 语义 | `0` 被读成"没就绪 / 扫描后为空"（t12 的零值混淆） | 表达真实事实 |

### 1.2 落点（`collect_pending()` 尾部，`for` 循环逐字未动）

```cpp
    /* … 遍历 + scan.set_ready(queued > 0) + 常驻孪生 5 次写 … */
    const std::size_t depth_after = deferred.size();   // 扫描后、运行预算前
    scan.finish(queued, depth_after);                  // ① 门控全局四量（W03 维护，只读引用）
    scan_acc_.add(scan.result());                      // ② 本 worker 常驻累加器（不写 gauge）
```

| 量 | 落点 | 门控 | 语义（⛔ 与既有量的区别） |
|---|---|---|---|
| `scan_ready_routes_total` | ①（`finish()` 内） | 是 | Σ 每轮**新入队 route 数**；与 `ready_observed`（**轮数**）**量纲不同、不得相加** |
| `deferred_depth_after_last` | ① `set_gauge`（无条件写含 0） | 是 | **扫描后**深度；与 `deferred_depth_last`（**入队前**）**不得混列** |
| `deferred_depth_after_max` | ① `max_gauge` | 是 | 扫描后深度峰值 |
| `deferred_depth_after_total` | ①（仅 `finished_`） | 是 | 逐轮 Σ，**唯一可安全按 worker 相加**的深度量 |
| `scan_ready_routes_total` / `deferred_depth_after_{last,max,total}` / `scan_elapsed_ns_total` | ②（`ScanRoundAccumulator`） | **否**（常驻） | 与①同点同值；池级 `after_last` = **Σ 每 worker** |

### 1.3 为什么两个落点都要（⛔ 不是重复）

- ① 是 t44 定义的**门控**面（`diagnostics_only=true`）：正式性能窗口按 W08 纪律**关诊断** ⇒ 只有①时，正式窗口里四个量全是"未采集"，W10/W11 读不到结束值。
- ② 是**常驻**面（`RecvWorkerStats` 追加字段，无时钟、无门控、per-worker），使 off 档也能读，并让"全池当前总深度 = Σ 每 worker"成为可算的量（R0-10 冻结）。
- 两者**同一位置、同一取值**写入 ⇒ diag=on 时逐值相等，构成本包 B1/B2 的自洽判据（实测：池级 `ready_routes` 常驻=门控=1184/1183/1186/694，`after_total` 常驻=门控=2368/2366/2372/1388）。

### 1.4 顺序为什么是"遍历 + set_ready 之后"

t44 的 `finish()` 文档允许在 `set_ready()` 前后任一点调用。本包取"之后"，于是 `result().elapsed_ns` 的区间与 `scan_time_ns_total`（构造 → 析构）**几乎重合**，两者可直接对账（§3.4）。`set_ready()` 与常驻孪生都不修改 `deferred`，故在它们之后读 `deferred.size()` 仍是"扫描后、运行预算前"的同一事实。

## 3. 判决性判据

### 3.1 单 gauge ≠ 全池总量（R0-10 的反例复现，`gauge.log`）

造法：直接建 **3 个独立 `RecvWorker`**（各自一份 `ScanRoundAccumulator`），每个注册 2 条"恒空 + has_pending 恒真"的本地 route ⇒ 3 个 worker **同时**有扫描后深度。

| 判据 | 实测 |
|---|---|
| A1 每 worker 有独立出参 | `w0=2 w1=2 w2=2`（非零 worker 数 = **3**） |
| **A2 单个 gauge 表达不了全池总量** | **Σ 每 worker = 6 > 门控 gauge = 2** |
| A3 gauge ≤ 单 worker 最大值（它只是"最后写入者"） | gauge=2 ≤ max=2 |
| A4 累计量可安全求和 | Σ 每 worker `after_total`=**294**；门控 `_total`=**294** |
| A5 两量语义可分 | 本场景 `scan_ready_routes_total`**正确为 0**（route 靠 `requeue` 续留、非本轮新入队）而 `after_last`=6 ⇒ 两量不同源、⛔ 不得互相替代 |

> ⚠️ 如实登记一处**期望值修正**：A5 的初版断言写成"`ready_routes>0`"，实测发现本场景下正确值是 **0**（这些 route 由 `run_budget()` 的 requeue 留在 deferred，`entry->queued` 未清 ⇒ 不是 `collect_pending()` 本轮新入队）。若保留原断言，就是**用错误期望值掩盖语义** —— 已改为"两量语义可分"并写明理由。真实新消息到达时的 >0 由 §2.2 的四档给出。

### 3.2 需求项 1 的四量语义（逐条机械核对）

- **量纲不得相加**（B4）：四档均满足 `Δscan_ready_routes_total ≥ Δscan_ready_rounds`（N=1000：694 vs 694；N=100：1183 vs 1183）。route 数口径 ≥ 轮数口径恒成立。
- **时点不得混列**（B3）：`deferred_depth_after_*`（扫描后）与 `deferred_depth_last/_max`（入队前）同窗口都有值且不同义；报告须分列。
- **同源自洽**（B1/B2）：常驻与门控两套在 diag=on 下**逐值相等**（池级 `ready_routes` 与 `after_total` 四档均相等）。
- **每 worker / 全池**（§3.1）：全池 `after_last` = Σ 每 worker。

### 3.3 diag=off = 「未采集」而非 0（`n*-diagoff.log`）

| 判据 | 实测（四档一致） |
|---|---|
| B1' **门控**四量恒 0 且 `counter_is_uncollected()==true` | 门控 `Δready_routes=0 Δafter_total=0 Δtime=0`，`counter_is_uncollected()=true` |
| B1' 同窗口**确实在扫**（0 不是"没扫"） | `Δrounds`=3729/3558/3537/2183（非 0） |
| B1'' **常驻**孪生仍可读且非 0 | `Δready_routes`=1183/1186/1179/694、`Δafter_total`=2366/2372/2358/1388 |
| B2' `elapsed` 亦为未采集（0），且不读时钟 | `Σelapsed=0`、`scan_time=0`（t44 已把 `clock_gettime` 完全置于门控内） |

⇒ **off 档的 0 是"未采集"**，⛔ 不得当"深度为 0"；本包用**两条面**分别断言，避免把两件事混列。

### 3.4 守恒判据（把 t44 的 "≈" 精确化）

t44 声明 `Σ result().elapsed_ns ≈ scan_time_ns_total` 可用。本轮实测发现**"≈"不够精确**（比值 0.53–0.95，不是接近 1），根因已定位：

- 两者**同起点**（`ScanRoundScope` 构造读的那一次钟）；
- **终点不同**：`elapsed_ns` 止于 `finish()` 内的读钟，`scan_time_ns_total` 止于**析构**读钟；
- ⇒ `scan_time − Σelapsed` = 「`finish()` 之后 → 析构读钟」这段**每轮固定**的尾部（本层接线为 `scan_acc_.add()` + 返回/展开 + 析构前几条语句）。

**判据因此改为两条可机械核对的形式（⛔ 不是放宽容差）**：

| 判据 | 实测 |
|---|---|
| B5a 严格序：`0 < Σelapsed ≤ scan_time`（同起点、终点更早 ⇒ 必为真；违反即接线位置错） | N=1: 338 803 ≤ 642 435；N=100: 1 236 603 ≤ 1 553 179；N=500: 2 634 452 ≤ 2 849 942；N=1000: 2 048 212 ≤ 2 156 380 |
| B5b 残差 = **每轮固定尾部**：`(scan_time−Σelapsed)/rounds ∈ [0.25×, 4×]` 同 run 标定值且 < 500 ns/轮 | 残差/轮 = **81.4 / 89.2 / 60.6 / 49.6 ns**，标定尾部（5 轮取 min）= **74.6–74.9 ns** |

**尾部常数标定**（`conserve.log`，100 万次 × 同形态；`--case conserve`）：
```
elapsed_ns/round = 10.29    tail_with_wiring = 76.52    tail_lib_only = 49.72    wiring_add = 26.80
```
⇒ 尾部 = 纯库析构（≈50 ns）+ 接线侧 `scan_acc_.add()`（≈27 ns）；后者就是本包接线引入的固定成本。

⛔ **报告纪律**：引用 `scan_time_ns_total` 时必须同时给出这条残差，**不得**把它当作"纯扫描耗时"；也不得用 `scan_time_ns_total` 换算 CPU core（墙钟区间，t44 已冻结该限定）。
