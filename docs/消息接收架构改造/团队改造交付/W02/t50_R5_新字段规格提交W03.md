## 0. 为什么必须进 schema（不是形式主义）

`field_schema.json` 是跨包读方（W11/W12/下游）确认「这个字段是什么意思、能不能加、空值表示什么」的**唯一事实来源**。
本轮新增的 5 个 gate 布尔与 `bad_header` **已经参与 `case_ok` 判定**（t47/W02-F3），
而 `currently_citable` / `run_identity` **决定引用权威**（t47/W02-F0、t50/R-3）。
⇒ 它们不在 schema 里，等于「判定与引用的关键字段没有登记」——正是 W03 §2.1 要防的形态。

## 1. `summary.csv` 新增列（6 个，全部逐 case）

| 列名 | 类型 | 单位 | nullable | 语义 | 来源 |
|---|---|---|---|---|---|
| `bad_header` | u64 | count | 否（无异常写 0） | 订阅侧「段头/对象结构自相矛盾」次数（`CheckOutcome.header_ok==false` 或长度不符；视图路径 `!view.valid()`/`d2.size()<kHdrSlots`） | `xproc_benchmark.cpp` 订阅循环 → 控制块 `sub_bad_header` → `CaseResult::bad_header` |
| `late_ok` | bool(0/1) | — | 否 | 迟发 gate 判定：`true`=未超预算。判定式 `late > manifests.failure_thresholds.late_abs_max` **且** `late/attempts > late_rate_max` 时为 `false` | 同文件 `run_one_case()` 单处判定（纪律②） |
| `backlog_ok` | bool(0/1) | — | 否 | 积压 gate：`backlog_max_ns/周期 > backlog_max_periods` 时 `false` | 同上 |
| `send_blocked_ok` | bool(0/1) | — | 否 | `send_blocked > send_blocked_max`（默认 0）时 `false` | 同上 |
| `abnormal_ok` | bool(0/1) | — | 否 | `abnormal > abnormal_max`（默认 0）时 `false` | 同上 |
| `bad_header_ok` | bool(0/1) | — | 否 | `bad_header > bad_header_max`（默认 0）时 `false` | 同上 |

**空值约定**：6 列**一律不写空**（即便未触发也写 `0`/`1`）⇒ 与 W03 §2.1 的「未测写空字段」不冲突：
这里是**已采集的判定结果**，不是未测项。⛔ 读方不得把 `0` 误解为「未采集」——`0` 的含义由列名后缀 `_ok` 确定。

## 2. `results.json` 新增键

| JSON 路径 | 类型 | nullable | 语义 |
|---|---|---|---|
| `cases[].bad_header` | number | 否 | 同 `summary.csv:bad_header` |
| `cases[].gates` | object | 否 | `{late_ok, backlog_ok, send_blocked_ok, abnormal_ok, bad_header_ok}` 五个 **bool**（与 summary 的 0/1 一一对应） |
| `manifest.failure_thresholds` | object | 否 | 见 §3 |
| `manifest.field_aliases` | object | 否 | 同一事实在不同产物里的列名映射（`late` ↔ `late_sends` 等） |
| `manifest.currently_citable` | string \| **null** | **是** | 现行 run 的**唯一权威指针**；`null` = 本轮未认领权威（缺 `--purpose` 或为复核轮且未给 `--citation-authority`） |
| `manifest.run_identity` | object | 否 | 见 §4 |
| `manifest.evidence_discipline` | object | 否 | 见 §5 |

## 3. `failure_thresholds`（判定预算，逐 case 可判）

| 键 | 类型 | 默认 | 语义 |
|---|---|---|---|
| `late_abs_max` | u64 | 20 | 迟发次数预算（与 `late_rate_max` **同时成立**才判失败） |
| `late_rate_max` | number | 0.05 | 迟发率预算（`late/attempts`） |
| `backlog_max_periods` | number | 10.0 | 峰值积压预算，单位 = **发送周期数**（跨速率档可比）；`0` = 不判、仅信息 |
| `send_blocked_max` | u64 | 0 | 有界等待耗尽次数预算 |
| `abnormal_max` | u64 | 0 | 结构异常样本预算 |
| `bad_header_max` | u64 | 0 | 段头矛盾预算 |
| `cli_overridden` | bool | false | 任一阈值被 CLI 覆盖 ⇒ `true`（复核轮会用它，读方须注意） |
| `gates` | array<string> | — | 进判定的 gate 名列表 |
| `gates_in_judgement` | object | — | 逐 gate 的**本 run 触发计数**（人可读字符串） |
| `informational_only` | object | — | **显式声明**哪些量只作信息性保留及理由（`via_view/via_object/via_dds/late_threshold_ns/backlog_sum_ns`） |

## 4. `run_identity`

| 键 | 类型 | 语义 |
|---|---|---|
| `this_run_id` | string | 本 run |
| `purpose` | enum | `evidence` / `verification` / `experiment`；**缺省时按 `verification` 记录** |
| `purpose_explicit` | bool | 命令行是否**显式**给了 `--purpose`（t50/R-3 新增） |
| `this_run_is_evidence` | bool | 仅当**显式** `--purpose=evidence` 且未给 `--citation-authority` 时为 true |
| `authority_undeclared` | bool | 本轮未声明权威 ⇒ 读方**不得**把它当现行 run |
| `claims_authority` | bool | 是否认领 `currently_citable` |
| `citation_authority` | string \| null | 显式指定的证据 run |

## 5. `evidence_discipline`（三条纪律 + 认领规则）

| 键 | 语义 |
|---|---|
| `current_run_authority` | 任何引用必须是 `currently_citable` 指向的 run；引用 `superseded_run_ids` 里的 run 必须标「非现行 + 原因」 |
| `authority_claim_rule` | **认领权威是显式动作**：只有 `--purpose=evidence` 才让 `currently_citable` 指向本 run；复核轮必须带 `--purpose=verification --citation-authority=<证据 run>`；机械判据 = 复核轮跑完后证据 run 的 `manifest.currently_citable` 不变（sha256 对比） |
| `single_judgement_logic` | `failure_reasons`（含 5 个 gate）只在 `run_one_case()` 一处产生；summary/results/verdict 只读该结果 |
| `zero_value_three_states` | `0`=已采集且为零 / `null`=未采集或分母为零（CSV 空字段）/ `unwired`=有定义无生产者（其 0 不可读作「未发生」） |
