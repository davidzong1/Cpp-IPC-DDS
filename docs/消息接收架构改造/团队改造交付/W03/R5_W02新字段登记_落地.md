## 1. 裁决（你点名要的那一处）

**三个字段 `currently_citable` / `run_identity` / `evidence_discipline` 我决定「进 schema」，但以新的登记类别进，而不是塞进测量字段表。**

理由（三条，都可核对）：

1. **它们确实是判定输入，不只是装饰**。`currently_citable` 决定"哪一份产物可以被引用"
   （t47/W02-F0、t50/R-3），`run_identity.authority_undeclared` 决定"读方能否把它当现行 run"。
   R-5 的缺陷本体就是"**判定与引用的关键字段没有登记**"——把判定输入排除在登记之外，
   等于把 R-5 的解法砍掉一半。
2. **但不能放进 `manifest_fields` 那种"测量字段"表**：那张表隐含"W03 拥有语义"。
   这些字段的语义归 W02（`--purpose` 的取值集合、权威认领规则都由 W02 的 CLI 决定）。
   混进去会造成"跨工作包语义漂移时 W03 被当成 owner"的责任错配。
3. **所以新增第三类登记 `run_level_fields[]`**，逐条带 `owner` / `registered_by` /
   `zero_semantics` / `semantics_source`，并在 schema 顶部用
   `structural_vs_measurement_registration` 把三类**用机器可读的方式**分开：

   | 类别 | 谁拥有 | 处置 |
   |---|---|---|
   | `measurable`（时基/时间戳/计数/相位/空闲/路径/开销） | **W03** | 原有 `sample_fields` / `manifest_fields` / `counter_fields`，语义不变 |
   | `run_orchestration`（`failure_thresholds` / `currently_citable` / `run_identity` / `evidence_discipline` / `field_aliases`） | **W02** | 本次登记结构，`owner="W02"`、`registered_by="W03"` |
   | `judgement_artifact`（5 个 gate 0/1 + `bad_header`） | **W02** | 本次登记，且标注**不适用"未测写空字段"纪律** |

⇒ **`bad_header` 与 5 个 gate 全部在内**（你要求的底线），且 `currently_citable` 等三项也一并登记，
只是**归属写清为 W02**。若你或 W12 认为三项仍应移出，删除 `run_level_field_table()` 中对应 4 条即可
（`run_identity`/`evidence_discipline`/`currently_citable`/`failure_thresholds` 各自独立），
其余登记不受影响 —— 它们没有硬依赖。

### 2.1 `summary.csv` 新增列 6 个（§1）

| 列名 | 登记类型 | 单位 | nullable | `zero_semantics` | owner |
|---|---|---|---|---|---|
| `bad_header` | `u64` | count | **false** | `measured_zero` | W02 |
| `late_ok` | `bool01` | - | **false** | `decided_zero` | W02 |
| `backlog_ok` | `bool01` | - | **false** | `decided_zero` | W02 |
| `send_blocked_ok` | `bool01` | - | **false** | `decided_zero` | W02 |
| `abnormal_ok` | `bool01` | - | **false** | `decided_zero` | W02 |
| `bad_header_ok` | `bool01` | - | **false** | `decided_zero` | W02 |

**空值约定已按你的要求显式登记**：这 6 列 `nullable=false`，`zero_semantics=decided_zero`
（gate）/ `measured_zero`（`bad_header`），描述里写明「**未触发也写 1/0，⛔ 不得读作未采集**」，
与 §2.1「未测写空字段」不冲突 —— 冲突面由 `zero_value_three_states` 段消解：
`decided_zero`（判定结果，两值都是结论）与 `uncollected_null`（未采集）**结构上分开**。
机器可用表头：`summary_csv_extra_header()` → `bad_header,late_ok,backlog_ok,send_blocked_ok,abnormal_ok,bad_header_ok`。

### 2.2 `results.json` 新增键（§2）

- `cases[].bad_header`（`number`，`measured_zero`）
- `cases[].gates`（`object`，`decided_zero`；五个 bool 与 summary 的 0/1 一一对应）

| 键 | 登记类型 | nullable | `zero_semantics` |
|---|---|---|---|
| `failure_thresholds` | `object` | false | `decided_zero` |
| `currently_citable` | `string\|null` | **true** | `uncollected_null` |
| `run_identity` | `object` | false | `decided_zero` |
| `evidence_discipline` | `object` | false | `decided_zero` |
| `field_aliases` | `object` | false | `decided_zero` |

`failure_thresholds` 的描述里**逐键列出**默认值与单位（`late_abs_max=20`、`late_rate_max=0.05`、
`backlog_max_periods=10.0`【**单位=发送周期数**，`0`=不判仅信息】、`send_blocked_max`/`abnormal_max`/

`manifest_extension_keys()` 给出 5 键清单供脚本机械遍历。

## 3. 顺带修掉的一处真实缺陷：`schema.csv` 未做 RFC4180 转义

追加字段时实测发现：`schema_document_csv()` **从不给含逗号的说明字段加引号**：

| 版本 | 列数不一致行数 |
|---|---|
| t52 之前（8 行） | 说明里含 `,` 的字段把一行拆成 8 列（如 `run_id`/`seq`/`generation`/`payload_checksum_ok`） |
| t52 追加后（19 行） | 新增字段说明含 `,` 更多 ⇒ 扩散 |

对"用 `csv` 模块整行读"的脚本是静默的（多出的列被吞进最后一列），但**按列取值**的读方会错位。
已加 `csv_escape()`（含 `,`/`"`/换行 ⇒ 整体加引号，内部 `"` 写 `""`）并覆盖**全部**五种 CSV 行型；
实测列数不一致行 **19 → 0**，并加 gtest 判据 `SchemaCsvIsWellFormed`（逐行统计列数，忽略引号内逗号）锁死。
⛔ 这是一处**追加字段时被暴露的既有缺陷**，不是本轮引入的；登记在此以免被读成"新缺陷"。

## 6. 我预判你会问的两点（先说清，避免 R-5 被误判）

1. **既有 W02 run 的 `field_schema.json` 仍是旧版**（例如 `artifacts/perf/20260928-r31-W02/`
   的 schema 里查不到这 6 列）。这不是落地失败：schema 由**W03 的生成器在运行时**写入，
   本包扩展的是生成器；**只有在新 run 里才会看到新段**。
   ⇒ 你的 §6 复核**必须对"本包之后新产生的 run"做**；对旧 run 做必然为 `False`，
   那反映的是旧 run 的时代，不是 R-5 未闭合。
   （我已在 `artifacts/perf/20260930-r48-W03-W02Fields/field_schema.json` 留了一份**新生成的**
   schema 供你直接核对；但它不是 W02 产物，⛔ 不可作为 W02 的证据 run。）
2. **`informational_only` 的"理由"字段**：我按 §3 只登记了它**存在**及其键名定位
   （"显式声明哪些量只作信息性保留及理由"），**没有**把五个理由的正文抄进 schema ——
   那些正文是 W02 判定语义的一部分，抄进来会在 W02 改动时产生"schema 与实现不一致"的漂移。
   若你希望正文也进 schema，请回告，我按你给的文本原样登记（仍标 `owner=W02`）。
