## 2. 新增字段定义（语义 / 单位 / nullable）

`counter_table()` 与 `field_schema.h` 的 `counter_fields` 同源生成，逐项如下：

| `CounterId` | 名称 | 单位 | category | nullable | 门控 | 语义（写清才不歧义） |
|---|---|---|---|---|---|---|
| `scan_ready_routes_total` | `scan_ready_routes_total` | `count` | `scan` | false（无证据写 0，与其它 count 一致） | 诊断 | **Σ 每轮新入队 route 数**（route **数**口径）。`/ scan_rounds` = 平均每轮新入队 route 数 |
| `deferred_depth_after_last` | `deferred_depth_after_last` | `count` | `scan` | false | 诊断 | 最近一轮**扫描后** deferred 深度（全局 gauge） |
| `deferred_depth_after_max` | `deferred_depth_after_max` | `count` | `scan` | false | 诊断 | 扫描后深度最大值（全局 gauge） |
| `deferred_depth_after_total` | `deferred_depth_after_total` | `count` | `scan` | false | 诊断 | **Σ 每轮扫描后深度**（唯一可安全按 worker 相加的深度量） |

> `nullable=false` 与"未采集"不冲突：**字段存在且为 0** 有两种含义，由
> `diagnostics_enabled` + `counter_is_diagnostics_only(id)` 机械区分（§4 A 档）。字段级 null
> 仍用于「该量在本运行中根本未定义」的情形（沿用 W03 既有 null 纪律）。

### 2.1 三个**不得混算**的显式声明（已同时写进代码注释与 schema）

`field_schema.h` 新增机器可读段 `counter_semantics_guards`：

| 对 | 规则 | 为什么 |
|---|---|---|
| `ready_observed` × `scan_ready_routes_total` | **不得相加** | 前者是**轮数**（本轮发现 ≥1 条就绪的轮数），后者是**route 数**；`routes/rounds` 才是"平均每轮新入队 route 数" |
| `deferred_depth_last` × `deferred_depth_after_last` | **不得互相覆盖、不得混列一列** | 前者 = 扫描**前**（入队前）快照，后者 = 扫描**后**快照（R0-10 要的量） |
| `deferred_depth_after_last` × 全池总深度 | **gauge 不得当全池总量** | `*_last/_max` 是全局 gauge：多 worker 并发时只保留"最后写入者"，全池**当前**总深度 = **Σ(每 worker 的 `ScanRoundResult::deferred_depth_after`)** |

**替代求法（R0-10）**：`ScanRoundAccumulator`（每 worker 一个实例，relaxed 原子，无锁）提供
`deferred_depth_after_last / _max / _total`、`ready_routes_total`、`rounds`、`ready_rounds`、
`elapsed_ns_total`；`aggregate_scan_rounds()` 给出
`deferred_depth_after_last_sum`（= 全池**当前**总深度）、`_total_sum`（Σ，可安全求和）、
`ready_routes_sum`、`rounds_sum`、`ready_rounds_sum` 与派生均值。

## 3. 关键实现决定（须由评审知晓）

1. **`_last` 无条件写（含 0）**：扫描后清空到 0 是正常状态；只在 `>0` 时写会让 gauge 保留
   上一轮的陈旧值（静默误导）。`_max` 单调递升。
2. **`finish()` 内的时钟读取完全落在诊断门控内**（实测直接决定门控是否有效）：
   门控外读时钟会让"关闭诊断"档从 **1.43 ns/轮** 涨到 **16.7 ns/轮**（见 §7 与交付验证记录）。
3. **`ScanRoundScope` 未调用 `finish()` 时**：新 4 个门控计数**一个都不写**，且
   `result().deferred_depth_after` 回退为"扫描前"值（**不给出假值**）；`elapsed_ns_collected=false`。
   另有 `finish_with_before_depth(ready_routes)` 供只想报就绪数的调用点使用。
4. **`scan_time_ns_total` 与 `result().elapsed_ns` 是同一区间**（构造 → `finish()`），
   因此 `Σ result().elapsed_ns ≈ scan_time_ns_total` 可作为"接线是否把 `finish()` 放在正确位置"
   的**守恒判据**（诊断开启时成立）。
5. **`deferred_depth_after_total / scan_rounds` 的分母口径**：只有在**每轮都调用 `finish()`** 时
   才是"平均扫描后深度"。按 worker 的均值请用 `ScanRoundAccumulator`（它只在 `add()` 时计轮）。
   取证时用 `finished()` / `result().elapsed_ns_collected` 逐轮断言。

## 5. `scan_time_ns_total` 区间 —— **冻结**（R0-9 明确要求）

**【区间】** `ScanRoundScope` **构造**（`collect_pending()` 内、**取到 `mtx` 之后**）
→ `finish()` 被调用的那一点；**含**遍历本身与调用方在 `finish()` 之前所做的一切
（当前接线中是 `for` 遍历 + `set_ready()` + 常驻孪生 5 次写；t42 实测）。

**与 R0-9「取得锁后 → 遍历结束」的关系 —— 如实登记，不宣称相符**：当前区间**比**期望多喂了
(a) `set_ready()`（一次 relaxed 布尔写，亚 ns 级）与 (b) 常驻孪生 5 次写（≈10 ns/轮）。

**冻结决定：保持既有区间（构造 → `finish()`/析构）**，理由：
1. 中途改区间会让 t30/t42/R2 的历史 `scan_time_ns_total` **不可比**（方案 §12 只追加纪律）；
2. 要精确到"取锁后 → 遍历结束"需调用点在遍历前后各打点并**只**把遍历区间交给库 —— R0-11 已把
   `recv_worker.cc` 的写入权判给共享层负责人，不属 W03 头文件职责；W03 只提供可表达该区间的通道
   （`result().elapsed_ns`，与 `scan_time_ns_total` **同区间**，两者可直接对账）；
3. 已具备**守恒性核对**：诊断开启时 `Σ result().elapsed_ns` ≈ `scan_time_ns_total`；
   ⛔ 不等本身就是"`finish()` 放错位置"的证据。

**三条限定（引用时必须同时带）**：
1. ⛔ 不得用 `scan_time_ns_total` 换算 CPU core（只覆盖 worker 线程被调度着跑的一小段，
   不含阻塞等待与调度延迟）；
2. ⛔ **含诊断/常驻自身开销**（见 §7 的分档实测），"开诊断"与"关诊断"读数不同源；
3. ⛔ **本接口落地前**采集的 `scan_time_ns_total` **不得用于判据**；落地后仅
   `ScanRoundScope::finished() == true` 的轮次可判据（其余轮 `elapsed_ns_collected == false`，
   属**未采集**）。
