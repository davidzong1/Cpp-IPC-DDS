## 2. §10.2 五项量（t30 接线后，计数器级读数）

**接线点**：`src/dzIPC/threepools/recv_worker.cc:233`（`ScanRoundScope scan(scanned, depth_in);`）—— `grep -rn ScanRoundScope src/` 现有真实落点（此前为 0）。
**采样**：24 组 = N(100/500/1000) × `N_worker`(4/8/16/32) × diag(off/on)，全部 rc=0；完整表见 `scan10.2/summary_table.tsv`。

### 2.1 五项量（diag=on 时门控面；diag=off 时门控恒 0 而常驻面非零）

| 量 | 定义（本 run 口径） | W=32 时随 N 的变化 |
|---|---|---|
| **每轮扫描 route 数** | `scanned_routes_total / scan_rounds` | 100 → **3.30**；500 → **15.83**；1000 → **31.44**（≈ N/32 = 每 worker 的在册 route 数） |
| **扫描耗时** | `scan_time_ns_total / scan_rounds` | 100 → **0.497 µs**；500 → **1.389 µs**；1000 → **2.092 µs**（随每轮 route 数线性） |
| **等待超时次数** | `wait_timeout_count`（窗口内） | 100 → 1779；500 → 1771；1000 → 1761（≈ 32 worker × 10/s × 6 s，**与 N 无关**） |
| **有效就绪比例** | `scan_ready_rounds / scan_rounds` | 100 → 0.1087；500 → 0.1098；1000 → 0.1095（≈ 常数） |
| **deferred 深度** | `deferred_depth_last/max` | max 6 / 13 / 8（有界，无累积） |

### 2.2 「线程 O(1) 但扫描 O(route)」在同一次运行里给出

- **线程账**（`threads_breakdown`）：`pool_workers=32 + control_scheduler=1 + orchestration=1 + residual=0`，
  在 N=100/500/1000 与 W=4/8/16/32 **完全一致**；`residual` 判据强制为 0（= per-topic 线程清零）。
- **扫描工作量**：同一 W 下 `scanned_routes_total ÷ N` 近似常数（W=32：30.2/86.1/85.9…；W=4：238/238/121 —— 后者的差异来自 W=4 时容量溢出 492 条走回退线程，见下）。
- **扫描轮数不随 N 增长**（W=32：2746 / 2720 / 2732）⇒ 成本 = 轮数 × 每轮 route 数。

### 2.3 容量边界（同一次运行内可判 `residual` 的性质）

W=4 且 N=1000 时：容量 `127×4=508`，溢出 **492** ⇒
`residual=492 = overflow=492 = seam 的 kRecvPathCompat(kWaitSetFull)=492`，且 `rx=1000`（**显式回退**，回退线程接住）。
⇒ 不受限档判 `residual==0`，受限档判 `residual==overflow`，避免把回退线程误报成泄漏。

### 2.4 diag off/on 的代价与建议

| 档 | 扫描耗时 | 说明 |
|---|---|---|
| diag=off | 门控五项 **恒 0**，常驻五项非零 | 正式性能窗口的默认档 |
| diag=on | 0.47–3.86 µs/轮（随每轮 route 数） | 仅"扫描耗时"需要门控 |

⇒ **本次读数在两种档下都采**；正式性能窗口建议 `diagnostics_enabled=false`（常驻面已覆盖 4/5 量）。
