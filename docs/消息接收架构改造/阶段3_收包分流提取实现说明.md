# 阶段 3 · 收包分流提取实现说明

> 状态：主线已落地。`SubState`、`process_received_buffer()` 及订阅循环调用点已实现；阶段 3 不引入线程池。
> 配套：`docs/消息接收架构改造/事件驱动线程池需求.md` §6、阶段 3；`docs/消息接收架构改造/shm_sub_thread_consolidation_plan.md` 阶段 3。
> 本阶段不改等待方式、不改线程数量、不引入 `RouteSession` 的等待协议（那是阶段 2）。两边都改订阅循环时，本阶段只拥有「`raw_data` 非空之后」的函数体，阶段 2 只拥有 `recv` 前后的 lease。

## 0. 要做什么

`shm_sub_ipc::InitChannel` 的 `subscribe_thread_` lambda 同时做两件事：等 `recv`，以及把 `buff_t` 分流进 `view_queue_` / `msg_queue_`。分流从 `raw_data` 非空开始，到 lambda 结束（`src/dzIPC/shm_pub_sub_ipc.cc` 订阅循环内，注释「双 wire 分流」那一段）。

阶段 5 的 worker 需要调用同一段逻辑，但不能把整个 `shm_sub_ipc` 或这条 lambda 搬进线程池。本阶段把它提成：

```cpp
void process_received_buffer(
    const std::shared_ptr<SubState>& state,
    ipc::buff_t&& raw_data);
```

调用点仍在原来的 `subscribe_thread_` 里。函数行为与搬之前逐条一致。

## 1. 边界

**搬进函数的**（现在位于 `raw_data.empty()` 判断之后）：

- 在 `topic_msg_mtx_` 下读取 `msg_id_`、`dzflat_schema_hash()`、是否可 view；
- `looks_like_dzflat` / `has_dzflat_magic` 分流；
- typed 话题：`msg_id`、schema 校验，借样推进 `view_queue_`；
- schema-less：adopt 配额、`dzflat_adopt` / `dzflat_read` 物化、`adopt_borrowed_` 增减；
- TLV：`AcceptWire` 后推进 `msg_queue_`；
- 现有 `detail::NoteDzFlatRx` 计数（id 不符、schema 丢弃、接受、段头损坏、adopt 溢出）。

**留在循环里的**：

- `running` / `handshake_completed` 判断；
- `recv`（阶段 2 之后是 lease + `recv`）；
- `raw_data.empty()` 则 `continue`。空 buffer 不调用本函数。

**不经过本函数的**：

- nodelet 快路径。发布端直接 `msg_queue_->push`，不产生 `buff_t`。
- `get` / `try_get` / `get_clone` / `try_get_clone`。它们只出队。
- 队列满时的 evict 回调仍挂在 `msg_queue_` 上，本阶段不改注册点。

## 2. SubState

`SubState` 是收包分流需要的那一份状态，由 `shm_sub_ipc` 持有 `shared_ptr<SubState>`，生命周期与订阅对象相同。不要在函数里保存 `shm_sub_ipc*`。阶段 5 的 worker 只拿 `SubState`。

至少包含：

| 字段 | 现在的位置 | 用途 |
|---|---|---|
| `topic_msg` + `topic_msg_mtx` | `shm_sub_ipc` | clone 模板、读 `msg_id` 和 schema hash |
| `msg_id` | `shm_sub_ipc::msg_id_` | 与段头比对。`reset_message` 改 id 时必须改这份，不能复制出第二份之后忘掉 |
| `view_queue` | `view_queue_` | DZFlat 借样 |
| `msg_queue` | `msg_queue_` | TLV 与 adopt/物化 |
| `adopt_cap` | `adopt_cap_` | 构造期确定，只读 |
| `adopt_borrowed` | `adopt_borrowed_` | adopt 成功 +1；函数内不负责 pop 和 evict 的 -1 |

`adopt_borrowed_` 的减量仍在两处，本阶段保持不动：

- `msg_queue_` 的 evict 回调（构造函数里注册）；
- `get_clone` / `try_get_clone` 出队时。

`reset_message` 今天在 `topic_msg_mtx_` 下更换模板并可能按新 `msg_id` 重新登记 nodelet。`SubState::msg_id` 与 `topic_msg` 必须是同一份，或者 `reset_message` 在同一把锁里更新 `SubState`。禁止分流线程读到新模板配旧 `msg_id`。

## 3. 函数契约

```cpp
void process_received_buffer(
    const std::shared_ptr<SubState>& state,
    ipc::buff_t&& raw_data);
```

- `state` 为空或 `raw_data` 为空：直接返回。调用方正常路径不会这样调。
- 按值拿走 `raw_data`。typed 借样路径把 buffer 移进 `Sample`；adopt 成功路径把 buffer 移进消息。调用返回后，调用方不得再使用这块 buffer。
- 校验失败、类型不匹配、`AcceptWire` 拒绝：函数返回，不入队。buffer 在函数内析构，chunk 按现有 `buff_t` 析构归还。计数与现在的 `continue` 相同。
- 不抛出到调用方。现有路径没有向外抛业务异常；若 `clone` 等抛了，与改前一样让线程退出，不在本阶段新加吞异常逻辑。
- 不调用 `recv`，不碰 `channel_mtx_` / `RouteSession`，不修改 `handshake_completed`。

实现方式：把现有代码块原样移入函数，把 `this->` 换成 `state->`。不顺手改配额公式、不调整 if 顺序、不合并两次 `topic_msg_mtx_` 加锁。那些都会改变和「借样期间是否还拿着锁」有关的行为。

## 4. 调用点

阶段 3 合入后，订阅循环的后半段变成：

```text
raw_data = recv(...)          // 阶段 2 未合入时仍是现在的持锁 recv(50)
if (raw_data.empty()) continue;
process_received_buffer(sub_state_, std::move(raw_data));
```

`sub_state_` 在 `shm_sub_ipc` 构造函数里和队列一起创建。`InitChannel` 不新建第二份队列。

## 6. 验收

用同一输入比较搬移前后，而不是只看「能收到」：

1. typed DZFlat，`msg_id` 与 schema 都匹配：入 `view_queue_`，不入 `msg_queue_`，`kDzFlatAccepted` +1，chunk 仍被 `Sample` 借住。
2. typed DZFlat，`msg_id` 不符：两个队列都不变，`kDzFlatIdSkipped` +1。
3. typed DZFlat，schema 不符：`kDzFlatSchemaDrop` +1，不入队。
4. magic 在但段头不合法：`kDzFlatHeaderBad` +1，不入队。
5. `GenericMessage` 且配额未满：`dzflat_adopt` 成功，`adopt_borrowed_` +1，入 `msg_queue_`。
6. 配额已满：走 `dzflat_read` 物化，`kDzFlatAdoptSpilled` +1，`adopt_borrowed_` 不增加，buffer 析构后 chunk 归还。
7. 手写类型收到 DZFlat：不入队（与现在的类型不匹配丢弃一致）。
8. TLV：`AcceptWire` 成功则入 `msg_queue_`；失败则不入队。
9. `reset_message` 换成新 `msg_id` 之后收到的下一条，按新 id 验收，不按旧 id。
10. nodelet 快路径仍直接 `push` `msg_queue_`，不调用本函数。出队路径的 `adopt_borrowed_` -1 仍然发生。

现有 SHM 订阅测试通过即可覆盖其中大部分。第 5、6 条若现有测试没有配额边界，补在 `test/` 里，不要靠手工看日志。

## 7. 明确不做

- 不把本函数放进线程池，不为它加批处理预算。
- 不把 `get`/`get_clone` 或用户回调并进本函数。
- 不改 view/adopt 上限、不改 evict 回调、不改 `AcceptWire`。
- 不在这里做多片重组的新缓存。重组仍在 `route::recv` 返回之前完成；本函数看到的是已经收齐的一块 `buff_t`。
- 不改 `recv` 的锁。那是阶段 2。若两阶段并行改同一 lambda，本阶段的 diff 只应出现在 `raw_data` 非空之后。

## 8. 当前实现与验收记录

- `include/dzIPC/shm_pub_sub_ipc.h` 新增 `SubState`，集中持有模板、`msg_id`、两个队列、adopt 配额与借样计数；`reset_message()` 在同一把状态锁下同步更新模板与 id。
- `src/dzIPC/shm_pub_sub_ipc.cc` 新增 `process_received_buffer(const std::shared_ptr<SubState>&, ipc::buff_t&&)`；函数包含唤醒伪影门、DZFlat/TLV 分流、schema/id 校验、adopt/spill、队列入队及统计计数。
- `subscribe_thread_` 保留阶段 2 的 `RouteSession` lease、`recv`、异常释放、判空和 seam 打点；非空 buffer 统一转移给 `process_received_buffer()`。未按 generation 丢弃已弹出的 buffer。
- `SubState` 的队列驱逐回调只捕获状态对象，不捕获 `shm_sub_ipc*`，为后续 worker 持有状态做生命周期准备。
