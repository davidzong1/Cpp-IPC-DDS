

# 2026.08.05

## 新增pub-sub心跳死连接回收

- 改动横跨 6 个文件，链路是 订阅端登记 bit + 心跳 → 控制面存活表 → 发布端超时判死 → libipc 定向断开。

### 1. include/dzIPC/common/control_plane.h — TopicControl 新增逐订阅者槽位表：
```c++
struct PeerSlot {
    std::atomic<uint32_t> in_use;        // 0=空闲 1=占用
    std::atomic<uint32_t> cc_id;         // 该订阅者在 libipc 连接位图中的 bit
    std::atomic<int32_t>  pid;           // 仅用于诊断
    std::atomic<uint32_t> generation;
    std::atomic<int64_t>  heartbeat_ns;
};
constexpr uint32_t kMaxPeerSlots = 64;   // 位图本身只有 32 位, 留一倍余量给重连期的槽位滞留
```

### 2. src/dzIPC/common/control_plane.cc — 四个新方法。两处并发细节：

- `acquire_peer_slot` 用 CAS 抢 in_use，然后才填 `cc_id/heartbeat_ns`。这中间有窗口，所以 `collect_stale_peers` 跳过 `cc_id==0 || heartbeat_ns==0` 的槽位，刚占用还没填完的不会被误判死。
- `release_peer_slot` 先清内容再放开 in_use。反过来的话槽位可能被别人抢占并填好，随后被本次的清零抹掉。
- `begin_rebuild()` 里加了 `clear_all_peer_slots()` —— 新 generation 会让所有订阅者重新 attach，旧 `cc_id` 随之作废，不清掉的话下一轮会拿旧 `cc_id` 去断新连接。

### 3–4. libipc 新增两个公开接口（chan_impl + chan_wrapper）：

```c++
static std::uint32_t connected_id(ipc::handle_t h);
static void disconnect_receivers(ipc::handle_t h, std::uint32_t cc_ids);
```
- `disconnect_receivers` 的注释里写明了责任边界：队列自己分不清死和慢，存活性由调用方负责，只能传确认 _push 越界的地方。

### 5. 订阅端 (sub_handshake)：
- attach 成功后 `acquire_peer_slot(gen, subscriber_->connected_id())`，循环 连/退出时 `release_peer_slot()`。

### 6. 发布端 (pub_handshake)：每 50ms

```c++
constexpr int64_t kPeerDeadTimeoutNs = 2'000'000'000LL;   // 200 个心跳周期
const uint32_t stale = control_plane_.collect_stale_peers(kPeerDeadTimeoutNs);
if (stale != 0 && publisher_ && publisher_->valid())
    publisher_->disconnect_receivers(stale);
```
